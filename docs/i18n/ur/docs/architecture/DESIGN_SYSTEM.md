> **حیثیت:** ڈیش بورڈ پر بنایا گیا ہے۔** Keak CI UI کٹ** (`@keak/cheaper-inference-ui-kit`)، ورک اسپیس `packages/ui-kit` کے طور پر فروخت کیا جاتا ہے (`@omniroute/ui-kit`؛ اپ اسٹریم اسنیپ شاٹ کو `packages/ui-kit/UPSTREAM.md` میں پن کیا جاتا ہے اور `npm run check:ui-kit-snapshot` کے ذریعے محفوظ کیا جاتا ہے)۔ روشنی کیننیکل تھیم ہے۔ پہلے سے طے شدہ ترجیح `system` ہے۔ پہلے سے طے شدہ پیلیٹ کٹ کا ہے۔** ایڈیشنز** ظاہری شکل (گرم کاغذ کے غیر جانبدار اور تانبے کا لہجہ `#e5ac82`, `packages/ui-kit/src/ci-editions.css`)؛ ترتیبات → ظاہری شکل → رنگ پیلیٹ پیش کرتا ہے۔** کلاسک** , چونے کے لہجے کے ساتھ کٹ کے بیس ٹوکن۔ سوئٹزر UI، ڈسپلے اور کوڈ ٹیکسٹ کے لیے واحد خاندان ہے (`--ci-font-ui`؛ `--ci-font-display` اور `--ci-font-mono` اسے حل کرتا ہے)، خود کٹ کے ذریعے میزبانی کرتا ہے (`packages/ui-kit/src/ci-fonts.css`، درآمد شدہ بذریعہ `ci-tokens.css`)۔ اسکرپٹس سوئٹزر میں گلائف کے ذریعے گلائف (`src/app/globals.css`) کی کمی ہے: سیریلک، یونانی اور ویتنامی کے لیے انٹر اور عربی رسم الخط کے لیے صرف `html[dir="rtl"]`، Vazirmatn کے تحت۔ ہر آئیکن ایک لوسائیڈ گلیف ہے۔

## 1. چیزیں کہاں موجود ہیں

- **کِٹ۔** `packages/ui-kit/src` اس upstream `src/` کی byte-for-byte نقل ہے جو
  `packages/ui-kit/UPSTREAM.md` میں درج commit پر pinned ہے (یہ فائل license authorization بھی ریکارڈ کرتی ہے)؛ `PATCHES.md` مقامی patches کی فہرست دیتا ہے (کوئی نہیں)۔ اسے source کے طور پر استعمال کیا جاتا ہے، build کے بغیر: `next.config.mjs` اسے transpile کرتا ہے، اور
  `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` اور `@omniroute/ui-kit/*` →
  `packages/ui-kit/src/*` کی mapping کرتا ہے (`vitest.config.ts` اور `vitest.mcp.config.ts` میں بھی یہی alias ہے)۔ کِٹ کے component کو اس کے subpath سے import کریں (`@omniroute/ui-kit/table`، `@omniroute/ui-kit/page-header`…)؛ کبھی بھی `@omniroute/ui-kit` barrel کے ذریعے نہیں: barrel ہر importer میں ہر component (date picker سمیت) شامل کر دیتا ہے۔ کِٹ کی stylesheet `src/app/globals.css` کے ذریعے شامل ہوتی ہے
  (`@import "../../packages/ui-kit/src/ci-styles.css"`، مکمل sheet: بنیادی
  `ci-ui.css` اور ہر pattern family)۔
- **Tokens۔** `packages/ui-kit/src/ci-tokens.css` میں `--ci-*` tokens declare کیے گئے ہیں؛ `src/app/globals.css`
  انہیں پرانے OmniRoute ناموں (`--color-*`، `--radius-*`،
  `--font-sans`/`--font-mono`، `--table-*`، `--orch-status-*`، `--color-fd-*`) سے bridge کرتا ہے، تاکہ موجودہ `var(--color-*)` reads اور Tailwind
  utilities کام کرتی رہیں۔ نیا code Tailwind utilities (`bg-surface`، `text-text-muted`،
  `border-border`، `text-success`، `bg-success-bg`، `bg-chart-1`…) یا کِٹ classes استعمال کرتا ہے — کبھی بھی hex value نہیں (`tests/unit/design-kit-bridge.test.ts` اس bridge کو enforce کرتا ہے)۔ `text-primary`، `--text-color-primary` کے ذریعے `--color-primary-ink` پر resolve ہوتا ہے، اس لیے primary text قابلِ مطالعہ رہتا ہے، جبکہ `bg-primary`/`border-primary` accent surface برقرار رکھتے ہیں: Editions کے تحت یہ کِٹ کا `--ci-color-accent-active` ہے (light میں گہرا copper `#99562f`، dark میں copper accent)؛ Classic کے تحت light میں lime-800 اور dark میں lime accent ہے۔ Chart series `--color-chart-1` … `--color-chart-8` استعمال کرتی ہیں، جن میں ہر ایک کے لیے text-safe `--color-chart-N-ink` اور opaque
  `--color-chart-N-subtle` chip tint ہے، اور انہیں کِٹ کے series order (`ciChartSeriesOrder`) کے مطابق assign کیا جاتا ہے۔
- **Themes۔** `<html className="ci-theme">` (`src/app/layout.tsx`) document کو کِٹ theme میں شامل کرتا ہے۔
  Preference `light`، `dark` یا `system` ہے (`THEME_CONFIG.defaultTheme = "system"` in
  `src/shared/constants/appConfig.ts`؛ `system`، `prefers-color-scheme` کی پیروی کرتا ہے)۔ `src/store/themeStore.ts` میں `applyTheme()` (جسے `THEME_BOOT_SCRIPT` بھی mirror کرتا ہے، یہ `src/app/layout.tsx` میں inline ہے اور hydration سے پہلے چلتا ہے) بیک وقت `data-theme="dark"|"light"` set کرتا ہے اور `<html>` پر `.dark` class کو toggle کرتا ہے۔ کِٹ کا dark token set `data-theme="dark"` پر keyed ہے (`packages/ui-kit/src/ci-tokens.css`)؛ OmniRoute کے اپنے dark overrides (`globals.css` کا `.dark` block) اور legacy Tailwind `dark:`
  utilities `.dark` class پر keyed ہیں۔ Accent color presets موجود نہیں: accent ہمیشہ کِٹ سے آتا ہے، اور کسی پرانے build سے محفوظ کیا گیا preset store load ہونے پر حذف کر دیا جاتا ہے۔
- **Palettes۔** دو palettes ہیں، دونوں کِٹ سے (`src/shared/constants/appearancePalette.ts`): `editions`، جو default ہے، اور `classic`۔ Editions `<html>` پر کِٹ کا `data-ci-appearance="editions"` attribute ہے، جسے
  `ci-editions.css` (`ci-ui.css` کے ذریعے imported) `data-theme` کے ساتھ combine کرتا ہے؛ Classic میں یہ attribute موجود نہیں ہوتا۔ Root layout اس attribute کو server-render کرتا ہے، اس لیے جس visitor کے پاس کچھ stored نہ ہو (یا JS نہ ہو) اسے ہر surface — dashboard، login، `/status`، error pages، `/docs` اور PWA — پر Editions ملتا ہے۔ انتخاب theme کے ساتھ اسی `theme` store میں persist ہوتا ہے (`palette`، `setPalette()`، `applyPalette()` in
  `src/store/themeStore.ts`) اور paint سے پہلے `THEME_BOOT_SCRIPT` کے ذریعے apply کیا جاتا ہے
  (`src/shared/utils/themeBootScript.ts`، layout کے `<head>` میں inlined)، جو attribute صرف اس وقت remove کرتا ہے جب stored palette `"classic"` ہو؛ `src/app/global-error.tsx`، جو root layout سے باہر ہے، اسی store سے اسے apply کرتا ہے۔ `data-ci-appearance` کسی دوسرے element پر نہ لگائیں: کِٹ اسے `html:root:has([data-ci-appearance="editions"])` کے ساتھ match کرتا ہے، اس لیے ایک descendant پورے document کو switch کر دے گا۔
  Editions کا `data-ci-editions-variant="landing"` variant marketing pages کے لیے ہے، dashboard کے لیے نہیں۔
  Browser chrome: server default، یعنی Editions، کو `viewport.themeColor` (ہر `prefers-color-scheme` کے لیے ایک tag) اور web manifest میں render کرتا ہے — `src/shared/constants/pwaThemeColors.ts` میں `PWA_THEME_COLORS`، جو Editions کے `--ci-color-background`
  (`#f3f1e9` / `#11120f`) کا واحد mirror ہے، اور `tests/unit/pwa-theme-colors.test.ts` کے ذریعے `ci-editions.css` پر pinned ہے۔ اس کے بعد live `<meta name="theme-color">` stored palette اور mode کی پیروی کرتا ہے: `THEME_BOOT_SCRIPT` paint سے پہلے tags کو rewrite کرتا ہے اور theme store کے actions ہر تبدیلی پر یہی کام کرتے ہیں (`resolveThemeColor()` /
  `applyThemeColor()` in `src/shared/utils/themeColorMeta.ts`، جہاں `CLASSIC_PAGE_BACKGROUND` کِٹ کے `ciTokens` سے read ہوتا ہے)۔ Explicit light/dark theme ہر tag کو اسی mode پر set کرتا ہے؛ `system` ہر scheme کے لیے ایک colour برقرار رکھتا ہے۔ Manifest Editions ہی رہتا ہے: اسے ہر install پر preference کے بغیر ایک بار fetch کیا جاتا ہے۔ Monaco اپنے colours ایک probe سے پڑھتا ہے (`monacoKitTheme.ts`)؛ Editions کے تحت probe read ایک synchronous pass کے لیے root کے `data-theme` کو flip کرتا ہے، کیونکہ کِٹ Editions light/dark کو root سے resolve کرتا ہے۔
- **Components (adapters)۔** `src/shared/components/index.tsx` OmniRoute component API (وہی names، default exports اور props) برقرار رکھتا ہے، اور اس کے پیچھے موجود primitives کِٹ کے اوپر adapters ہیں: forms
  (`Button`، `Input`، `Textarea`، `Checkbox`، `Select`، `Toggle`، `Badge`، `Card`)، overlays اور feedback
  (`Modal`/`ConfirmModal`، `Tooltip`/`InfoTooltip`، `NotificationToast`، `EmptyState`، `Loading`)،
  structure (`Collapsible`، `CollapsibleSection`، `SegmentedControl`، `Breadcrumbs`، `Avatar`) اور tables
  (`DataTable`، `FilterBar`، `ColumnToggle`، `FilterPills`، `PresetSlider`)۔ ایک adapter کِٹ component کو subpath کے ذریعے import کرتا ہے اور legacy props کو اس پر map کرتا ہے — مثال کے طور پر `Button variant="primary"` کِٹ کا `default` button ہے (`--ci-button-primary-*`: light میں inverse surface، dark میں اس کے `--ci-color-accent-foreground` ink کے ساتھ accent)، `danger`، `destructive` ہے، اور `warning`، `outline` کے ساتھ `.ci-button--warning` extension ہے۔ `globals.css` کے آخر میں موجود `.ci-button--warning` اور `.ci-badge[data-tone]` rules (`@layer components`) کِٹ classes کے اوپر OmniRoute extensions ہیں۔
  `tests/unit/ui/adapters/*.test.tsx` ہر adapter کو pin کرتے ہیں۔
- **شیل۔** `src/app/(dashboard)/layout.tsx`، `DashboardLayout` کو رینڈر کرتا ہے، جو
  `src/shared/components/layouts/DashboardShell.tsx` کو رینڈر کرتا ہے: کِٹ کا `SidebarProvider` /
  `Sidebar` / `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`)، جبکہ OmniRoute کی نیویگیشن منطق
  `src/shared/components/Sidebar.tsx` میں ہے۔ `#main-content` تک "مواد پر جائیں" لنک فوکس کیے جانے کے قابل
  عناصر میں پہلا ہے۔ `src/shared/components/Header.tsx` میں کِٹ کا `SidebarTrigger` (شیل کا واحد سائڈبار
  ٹوگل)، Keak کا `ProductSwitcher` اور کمانڈ پیلیٹ کھولنے والا شامل ہے؛ یہ روٹ کا عنوان صرف اس وقت دکھاتا ہے
  جب `#main-content` کے اندر کِٹ کا کوئی `PageHeader` (`.ci-page-header`) ماؤنٹ نہ ہو، اس لیے اپنے
  `PageHeader` والے صفحے میں ایک ہی `h1` ہوتا ہے۔ `src/shared/components/CommandPalette.tsx` کِٹ کا
  `Dialog` ہے۔
- **آئیکنز۔** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`)، اسکرینز میں استعمال ہونے والی
  Material Symbols کی لغت کے نام کو `ICON_MAP` (`src/shared/constants/iconMap.ts`) کے ذریعے Lucide گلف سے
  حل کرتا ہے۔ Material Symbols فونٹ اور پیکیج ختم کر دیے گئے ہیں: میپ میں موجود نہ ہونے والا نام ایک غیر جانب
  دار پلیس ہولڈر گلف (`data-icon-missing="true"`) رینڈر کرتا ہے اور پروڈکشن کے علاوہ کنسول وارننگ لاگ کرتا ہے۔
  `npm run gen:icon-map` استعمال میں موجود وہ نام پرنٹ کرتا ہے جو میپ میں موجود نہیں
  (`tests/unit/icon-map-coverage.test.ts` ایسے ہر نام پر ناکام ہوتا ہے جس کے لیے Lucide آئیکن موجود نہ ہو؛
  `tests/unit/icon-map-object-values.test.ts` لک اَپ آبجیکٹس میں محفوظ ناموں کا احاطہ کرتا ہے)؛
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` لفظی
  `<span className="material-symbols-outlined">` اسپینز کو `<Icon>` میں دوبارہ لکھتا ہے۔
- **برانڈ۔** `src/shared/components/OmniRouteLogo.tsx` کِٹ کو ریپ کرتا ہے: ڈیفالٹ ایکسپورٹ `OmniRouteLogo`
  `ProductIcon product="omniroute" variant="glyph"` (ان لائن SVG، `basePath` سے محفوظ) رینڈر کرتا ہے،
  جبکہ `OmniRouteLockup`، `ProductLockup product="omniroute"` (قابلِ رسائی نام "Keak OmniRoute") رینڈر کرتا ہے
  یا، وائٹ لیبل آپریٹرز کے لیے، ان کا اپنا `name`/`logoSrc` رینڈر کرتا ہے۔ پروڈکٹ سوئچر کی منزلیں
  `src/shared/constants/keakProducts.ts` (`KEAK_PRODUCT_LINKS`، `KEAK_ACTIVE_PRODUCT`) میں موجود ہیں۔
  اسٹینڈ الون اسکرینز — `src/app/login/page.tsx`، `src/app/status/page.tsx`،
  `src/app/maintenance/page.tsx`، `src/app/offline/page.tsx`، `src/app/not-found.tsx` اور
  `src/shared/components/ErrorPageScaffold.tsx` — لاک اَپ دکھاتی ہیں؛
  `tests/unit/brand-pages-static.test.ts` اس کی حفاظت کرتا ہے۔

## 2. قواعد

1. کبھی لفظی قدریں نہیں، صرف ٹوکنز۔ جان بوجھ کر رکھی گئی مستثنیات: ہمیشہ تاریک کنسول ٹرمینل اور
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`)، جو ان کالرز کے لیے کِٹ کے اسٹیٹس
   پیلیٹ کا resolved-hex عکس ہے جنہیں لفظی hex درکار ہوتا ہے۔ اب categorical پیلیٹس بھی کوئی
   استثنا نہیں ہیں: یہ کِٹ کے آٹھ chart ٹوکنز (`--color-chart-1..8`، نیز `-ink`/`-subtle`) پر،
   کِٹ کی سیریز کی ترتیب میں، `src/shared/utils/categoricalPalette.ts` کے ذریعے چلتے ہیں، اور
   routing strategies کے لیے `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` کے ذریعے؛
   ReactFlow edges اور orchestration canvas theme-aware `--orch-status-*` متغیرات پڑھتے ہیں
   (`src/shared/components/flow/edgeStyles.ts`)۔
2. `packages/ui-kit/src` میں کبھی ہاتھ سے تبدیلی نہ کریں: `scripts/dev/sync-ui-kit.sh <commit>` کے
   ساتھ sync کریں؛ pre-commit gate `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) pinned
   upstream commit سے مختلف کسی بھی byte پر ناکام ہو جاتا ہے (upstream clone،
   `UI_KIT_CLONE` یا `_references/cheaper-inference-ui-kit` موجود نہ ہونے پر یہ warning کے ساتھ
   skip ہو جاتا ہے)۔ جب کِٹ میں کوئی چیز موجود نہ ہو تو adapter یا screen میں اس کا متبادل بنائیں
   اور upstream سے اس کے لیے کہیں۔
3. کِٹ کے متنی defaults انگریزی میں ہوتے ہیں (`label = "Loading"`، `loadingLabel = "Loading table"`…) —
   جب بھی کِٹ کا کوئی component متن render کرے، `useTranslations(...)` سے ترجمہ شدہ strings پاس کریں۔
4. Tailwind utilities کِٹ component classes پر غالب آتی ہیں (کِٹ
   `@layer theme, base, components, utilities` کا اعلان کرتا ہے اور اس کے rules `components` میں
   موجود ہیں) — spacing اور layout کے لیے utilities استعمال کریں، کِٹ components کا رنگ بدلنے کے لیے نہیں۔
5. Headings: page اور section titles کے لیے `.ci-heading`؛ `.ci-dashboard-display` صرف بڑے،
   کم متن والے display text کے لیے، جیسے error-page status code۔ دونوں Switzer استعمال کرتے ہیں۔
6. `tests/unit/dashboard-kit-sweep.test.ts` کِٹ کے adoption کی نگرانی کرتا ہے: `src/app` یا
   `src/shared/components` کے تحت کوئی Material ligature span نہیں؛ dashboard tree
   (`src/app/(dashboard)` اور `src/shared/components`) میں کوئی raw `<select>`، `<textarea>` یا
   `<table>` نہیں، اور فہرست شدہ exceptions (یعنی `Select` adapter کی native branch،
   `RequestLoggerDetail`) کے علاوہ ہاتھ سے بنایا گیا کوئی `role="dialog"` نہیں؛ وہاں ہر raw
   `<button>` یا `<input>` کے لیے اس سے زیادہ سے زیادہ 3 سطریں اوپر ایک ایسا comment درکار ہے
   جس میں وجہ سمیت `kit-exception:` شامل ہو؛ palette hues اور `dark:` variants صرف انہی files میں
   ہو سکتے ہیں جنہیں test فہرست میں شامل کرتا ہے۔

## 5. کٹ کو اپ ڈیٹ کرنا

`npm run check:ui-kit-upstream` اپ اسٹریم ریپو کے تازہ ترین `v*` ٹیگ کے ساتھ `packages/ui-kit/UPSTREAM.md` میں پن کیے ہوئے ورژن کا موازنہ کرتا ہے اور جب کوئی ریلیز ختم ہوتا ہے تو sync کمانڈ پرنٹ کرتا ہے۔

روزانہ `UI Kit upstream watch` ورک فلو (`.github/workflows/ui-kit-upstream-watch.yml`) ایک ہی چیک چلاتا ہے۔ جب پن پیچھے ہے، `scripts/ci/ui-kit-sync-pr.sh` ایک سنک PR سب سے زیادہ `release/vX.Y.Z` برانچ کے خلاف، رولنگ برانچ `chore/ui-kit-sync-latest` پر کھلا رکھتا ہے۔ یہ کبھی ضم نہیں ہوتا ہے: ہر کٹ ریلیز کو اب بھی مقامی VPS پر ایک بصری جانچ کی ضرورت ہے۔ برانچ کو دوبارہ تعمیر کیا جاتا ہے جب ایک نئی ریلیز باہر ہوتی ہے اور دوسری صورت میں اسے تنہا چھوڑ دیا جاتا ہے۔ ہاتھ سے دھکیلنے والے کمٹ کے ساتھ ایک کھلا PR اوور رائٹ نہیں ہوتا ہے، اور ایک ایسے ورژن کے لیے PR جسے دیکھ بھال کرنے والے نے غیر انضمام شدہ بند کر دیا ہے، نئی ریلیز تک بند رہتا ہے۔

جب کوئی PR نہیں کھولا جا سکتا ہے (ٹارگٹ ریلیز منجمد ہے، PR نے ہاتھ سے دھکیل دیا ہے، PR بند کر دیا گیا ہے، یا کوئی PR ٹوکن سیٹ نہیں ہے) ورک فلو ایک ٹریکنگ ایشو کو کھلا رکھتا ہے جو کہتا ہے۔

ورک فلو دو راز استعمال کرتا ہے:

- `secrets.UI_KIT_READ_TOKEN`: نجی اپ اسٹریم ریپو کے لیے صرف پڑھنے کے لیے ٹوکن۔ جب ورک فلو اپ اسٹریم کو نہیں پڑھ سکتا ہے (کوئی ٹوکن نہیں، ایک ٹوکن جس نے کام کرنا بند کردیا، یا GitHub ناقابل رسائی) رن سبز رہتا ہے لیکن ایک انتباہ لکھتا ہے اور ایک الگ مسئلہ کھلا رکھتا ہے، جو بعد میں چلنے کے بعد اپ اسٹریم کو دوبارہ پڑھ سکتا ہے۔
- `secrets.UI_KIT_SYNC_PR_TOKEN`: اس ریپوزٹری پر ایک عمدہ ٹوکن جس میں مواد اور پل کی درخواستیں تحریری رسائی ہے۔ پہلے سے طے شدہ `GITHUB_TOKEN` یہاں PRs نہیں بنا سکتا، اور PR اسے کھولنے سے CI متحرک نہیں کیا جائے گا۔ اس ٹوکن کے بغیر ورک فلو صرف برانچ کو آگے بڑھاتا ہے۔

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` upstream `src/` اس کمٹ پر کاپی کرتا ہے (`latest` = جدید ترین `v*` ٹیگ) `packages/ui-kit/src` میں، واحد اجازت شدہ تبدیلی کو لاگو کرتا ہے (یہ متعلقہ درآمدات سے `.js` لاحقہ گرتا ہے)، اور `packages/ui-kit/package.json` اور `package-lock.json` میں ورک اسپیس ورژن کو اپ اسٹریم والے پر سیٹ کرتا ہے۔ پھر: `git diff packages/ui-kit` کا جائزہ لیں، دونوں تھیمز میں فراہم کنندگان، ترتیبات، کومبوز، استعمال اور اختتامی نقطہ پر ایک بصری پاس کریں، `npm run check:ui-kit-snapshot` اور `npm run test:vitest:ui` چلائیں، اور PR اپ اسٹریم چینج لاگ کے ساتھ کھولیں۔
