> **ሁኔታ፡** ዳሽቦርዱ የተገነባው በ** Keak CI UI ኪት** (`@keak/cheaper-inference-ui-kit`)፣ እንደ የሥራ ቦታ `packages/ui-kit` (`@omniroute/ui-kit`፣ የላይኛው ዥረት ቅጽበታዊ ገጽ እይታ በ `packages/ui-kit/UPSTREAM.md` ላይ ተሰክቷል እና በ `npm run check:ui-kit-snapshot` ይጠበቃል)። ብርሃን ቀኖናዊ ጭብጥ ነው; ነባሪው ምርጫ `system` ነው። ነባሪው ቤተ-ስዕል የኪት ነው።** እትሞች** መልክ (ሞቃታማ የወረቀት ገለልተኝነቶች እና የመዳብ ዘዬ `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); ቅንብሮች → መልክ → የቀለም ቤተ-ስዕል ያቀርባል** ክላሲክ** ፣ የኪቱ መሠረት ቶከኖች ከኖራ ዘዬ ጋር። ስዊዘርዘር ለ UI፣ የማሳያ እና ኮድ ጽሑፍ (`--ci-font-ui`፣ `--ci-font-display` እና `--ci-font-mono` መፍታት ያለበት) ነጠላ ቤተሰብ ነው፣ በራሱ በራሱ የሚስተናገደው (`packages/ui-kit/src/ci-fonts.css`፣ በ `ci-tokens.css` የመጣ)። ስክሪፕቶች ስዊዘርላንድ ይጎድላቸዋል glyph በ glyph (`src/app/globals.css`): ኢንተር ለሲሪሊክ፣ ግሪክ እና ቬትናምኛ እና፣ በ `html[dir="rtl"]` ስር ብቻ፣ ቫዚርማትን ለአረብኛ ፊደል። እያንዳንዱ አዶ የሉሲድ ግሊፍ ነው።

## 1. ነገሮች የሚገኙበት ቦታ

- **ኪት።** `packages/ui-kit/src` በ`packages/ui-kit/UPSTREAM.md` ውስጥ በተወሰነው commit ላይ ያለው የupstream `src/` ከbyte-for-byte ተመሳሳይ ቅጂ ነው (ፋይሉ የፈቃድ ፍቃድንም ይመዘግባል)፤ `PATCHES.md` የአካባቢ ማሻሻያዎችን ይዘረዝራል (ምንም የሉም)። እንደ source ይጠቀማል፣ build የለውም፦ `next.config.mjs` ያስተላልፈዋል፣ `tsconfig.json` ደግሞ `@omniroute/ui-kit` → `packages/ui-kit/src` እና `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` ያያይዛል (`vitest.config.ts` እና `vitest.mcp.config.ts` ተመሳሳይ alias ይይዛሉ)። የኪት ኮምፖነንትን በsubpath (`@omniroute/ui-kit/table`፣ `@omniroute/ui-kit/page-header`…) ያስገቡ፤ በ`@omniroute/ui-kit` barrel በኩል በፍጹም አያስገቡ። ምክንያቱም barrel እያንዳንዱን ኮምፖነንት (date pickerን ጨምሮ) ወደሚያስገባው እያንዳንዱ importer ይጎትታል። የኪት stylesheet በ`src/app/globals.css` ይገባል (`@import "../../packages/ui-kit/src/ci-styles.css"`፤ ሙሉ sheet፦ ዋናው `ci-ui.css` እና ሁሉም የpattern ቤተሰቦች)።
- **Tokens።** `packages/ui-kit/src/ci-tokens.css` የ`--ci-*` tokensን ያውጃል፤ `src/app/globals.css` እነዚህን ወደ የቆዩ የOmniRoute ስሞች (`--color-*`፣ `--radius-*`፣ `--font-sans`/`--font-mono`፣ `--table-*`፣ `--orch-status-*`፣ `--color-fd-*`) ያገናኛቸዋል፣ ስለዚህ ያሉት `var(--color-*)` ንባቦች እና Tailwind utilities መስራታቸውን ይቀጥላሉ። አዲስ ኮድ የTailwind utilities (`bg-surface`፣ `text-text-muted`፣ `border-border`፣ `text-success`፣ `bg-success-bg`፣ `bg-chart-1`…) ወይም የኪት ክላሶችን ይጠቀማል — በፍጹም hex እሴት አይጠቀምም (`tests/unit/design-kit-bridge.test.ts` ድልድዩን ያረጋግጣል)። `text-primary` በ`--text-color-primary` በኩል ወደ `--color-primary-ink` ይፈታል፣ ስለዚህ ዋና ጽሑፍ ሊነበብ የሚችል ሆኖ ይቆያል፤ `bg-primary`/`border-primary` ደግሞ የaccent ላይን ይጠብቃሉ፦ በEditions ስር የኪቱ `--ci-color-accent-active` (በብርሃን ሁነታ ጥልቅ መዳብ `#99562f`፣ በጨለማ ሁነታ የመዳብ accent) ነው፤ በClassic ስር ደግሞ በብርሃን ሁነታ lime-800 እና በጨለማ ሁነታ የlime accent ነው። የchart ተከታታዮች `--color-chart-1` … `--color-chart-8` ይጠቀማሉ፤ እያንዳንዱም ጽሑፍ-ደህንነቱ የተጠበቀ `--color-chart-N-ink` እና ግልጽነት የሌለው `--color-chart-N-subtle` chip tint አለው፣ እነሱም በኪቱ የseries ቅደም ተከተል (`ciChartSeriesOrder`) ይመደባሉ።
- **Themes።** `<html className="ci-theme">` (`src/app/layout.tsx`) ሰነዱን ወደ የኪት theme ያስገባል። ምርጫው `light`፣ `dark` ወይም `system` ነው (`THEME_CONFIG.defaultTheme = "system"` በ`src/shared/constants/appConfig.ts` ውስጥ ነው፤ `system` የ`prefers-color-scheme` ቅንብርን ይከተላል)። በ`src/store/themeStore.ts` ያለው `applyTheme()` (በ`src/app/layout.tsx` ውስጥ inline በሆነው `THEME_BOOT_SCRIPT` የተደገመው፣ hydration ከመካሄዱ በፊት የሚሰራው) `data-theme="dark"|"light"` ያዘጋጃል እና በ`<html>` ላይ `.dark` classን በአንድ ጊዜ ያብራል/ያጠፋል። የኪቱ የጨለማ token ስብስብ በ`data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) ላይ ይመሰረታል፤ የOmniRoute የራሱ የጨለማ overrides (`globals.css` ውስጥ ያለው `.dark` block) እና የቆዩ Tailwind `dark:` utilities ደግሞ በ`.dark` class ላይ ይመሰረታሉ። የaccent ቀለም presets የሉም፦ accent ሁልጊዜ ከኪቱ ይመጣል፣ እና ከአሮጌ build የተቀመጠ preset store ሲጫን ይሰረዛል።
- **Palettes።** ሁለት ናቸው፣ ሁለቱም ከኪቱ የመጡ (`src/shared/constants/appearancePalette.ts`)፦ `editions`፣ ነባሪው፣ እና `classic`። Editions በ`<html>` ላይ የኪቱ `data-ci-appearance="editions"` attribute ነው፤ `ci-editions.css` (በ`ci-ui.css` የሚገባው) ይህንን ከ`data-theme` ጋር ያጣምረዋል፤ Classic ደግሞ attribute አለመኖሩ ነው። Root layout ይህን attribute በserver ያቀርባል፣ ስለዚህ ምንም ያልተቀመጠለት (ወይም JS የሌለው) ጎብኚ Editionsን በእያንዳንዱ surface — dashboard፣ login፣ `/status`፣ error pages፣ `/docs` እና PWA — ላይ ያገኛል። ምርጫው ከtheme ጋር በተመሳሳይ `theme` store (`palette`፣ `setPalette()`፣ `applyPalette()` በ`src/store/themeStore.ts`) አጠገብ ይቀመጣል፣ እና ከpaint በፊት በ`THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`፣ በlayout ውስጥ `<head>` ላይ inline የተደረገው) ይተገበራል፤ ይህም attributeን የሚያስወግደው የተቀመጠው palette `"classic"` ሲሆን ብቻ ነው። `src/app/global-error.tsx`፣ ከroot layout ውጭ ያለው፣ ከዚያው store ይተገብረዋል። `data-ci-appearance`ን በማንኛውም ሌላ element ላይ አታስቀምጡ፦ ኪቱ ከ`html:root:has([data-ci-appearance="editions"])` ጋር ያዛምደዋል፣ ስለዚህ አንድ descendant ብቻ መላውን ሰነድ ይቀይራል። የEditions `data-ci-editions-variant="landing"` variant ለmarketing pages ነው፣ ለdashboard አይደለም። የbrowser chrome ሁኔታ፦ server ነባሪውን Editionsን በ`viewport.themeColor` (በእያንዳንዱ `prefers-color-scheme` አንድ tag) እና በweb manifest ያቀርባል — `src/shared/constants/pwaThemeColors.ts` ውስጥ ያለው `PWA_THEME_COLORS`፣ የEditions `--ci-color-background` (`#f3f1e9` / `#11120f`) ብቸኛው mirror፣ በ`tests/unit/pwa-theme-colors.test.ts` ወደ `ci-editions.css` የተያያዘው ነው። ከዚያ የlive `<meta name="theme-color">` የተቀመጠውን palette እና mode ይከተላል፦ `THEME_BOOT_SCRIPT` tagsን ከpaint በፊት እንደገና ይጽፋል፣ እና የtheme store actions በእያንዳንዱ ለውጥ ያደርጉታል (`resolveThemeColor()` / `applyThemeColor()` በ`src/shared/utils/themeColorMeta.ts`፣ `CLASSIC_PAGE_BACKGROUND` ከኪቱ `ciTokens` የሚነበብ)። ግልጽ light/dark theme እያንዳንዱን tag ## 4. አዳፕተር መጨመር ወይም መለወጥ

1. የ `src/shared/components/index.tsx`ን ሕዝባዊ API ይጠብቁ፡ ተመሳሳይ የኤክስፖርት ስሞች፣ ነባሪ ኤክስፖርቶች እና
   የሚቀበሉ props። ድሮዎቹን (legacy) props በአዳፕተሩ ውስጥ ወደ ኪቱ ያምሩ (ይመልከቱ `Button.tsx`: `VARIANT_TO_KIT`፣
   `SIZE_TO_KIT`)።
2. ኪቱን በንዑስ-መንገድ (subpath) ያስገቡ (`@omniroute/ui-kit/<component>`)።
3. የኪት ክፍተቶችን ለማለፍ የሚደረጉ ዙሪያ-መፍትሔዎች (workarounds) በአዳፕተሩ ውስጥ ይኑሩ (ማስተካከያው ቅጥ/ስታይል ከሆነ ወይም
   በ `globals.css` `@layer components` ውስጥ)፣ በ `packages/ui-kit/src` ውስጥ ግን በፍጹም አይደሉም።
4. `tests/unit/ui/adapters/<name>.test.tsx`ን ይጨምሩ ወይም ያዘምኑ። ብዙ ጠሪዎች (callers) ላሉት አዳፕተር፣ ከለውጡ
   በፊት እና በኋላ የተሰራውን ማርክአፕ ያወዳድሩ — የpadding ወይም የማጠቂያ (wrapper) ለውጦች ወደ እያንዳንዱ ማያ ገጽ ይስፋፋሉ።

## 5. ኪት ማዘመን

`npm run check:ui-kit-upstream` በ `packages/ui-kit/UPSTREAM.md` ውስጥ የተሰካውን ስሪት ከአዲሱ `v*` መለያ ጋር ያወዳድራል እና ልቀቱ ሲወጣ የማመሳሰል ትዕዛዙን ያትማል።

የየቀኑ `UI Kit upstream watch` የስራ ፍሰት (`.github/workflows/ui-kit-upstream-watch.yml`) ተመሳሳይ ፍተሻ ይሰራል። ፒኑ ከኋላ እያለ፣ `scripts/ci/ui-kit-sync-pr.sh` አንድ የማመሳሰል PR ከከፍተኛው `release/vX.Y.Z` ቅርንጫፍ ጋር፣ በሚንከባለል ቅርንጫፍ `chore/ui-kit-sync-latest` ላይ ክፍት ያደርገዋል። በፍፁም አይዋሃድም፡ እያንዳንዱ ኪት መለቀቅ አሁንም በአካባቢው VPS ላይ የእይታ ፍተሻ ያስፈልገዋል። ቅርንጫፉ የሚገነባው አዲስ ልቀት ሲወጣ እና ካልሆነ ብቻውን ሲተው ነው። የተከፈተ PR በእጅ የተገፈፈ አልተፃፈም፣ እና ጠባቂ የተዘጋው አንድ PR አዲስ እስኪወጣ ድረስ ተዘግቶ ይቆያል።

ምንም PR መክፈት በማይቻልበት ጊዜ (የታለመው መልቀቅ በረዶ ሲሆን, PR በእጅ ተገፋ, PR ተዘግቷል, ወይም ምንም PR ቶከን አልተዘጋጀም) የስራ ሂደቱ ለምን እንደሆነ የሚገልጽ አንድ የመከታተያ ጉዳይ ይከፍታል.

የአሰራር ሂደቱ ሁለት ምስጢሮችን ይጠቀማል-

- `secrets.UI_KIT_READ_TOKEN`፡ ለግል ወደ ላይ ለሚደረገው ሪፖ ተነባቢ-ብቻ ማስመሰያ። የስራ ፍሰቱ ወደ ላይ ማንበብ በማይችልበት ጊዜ (ምንም ማስመሰያ፣ መስራት ያቆመ ቶከን፣ ወይም GitHub የማይደረስበት) ሩጫው አረንጓዴ ሆኖ ይቆያል ነገር ግን ማስጠንቀቂያ ይጽፋል እና አንድ የተለየ እትም ክፍት ያደርገዋል፣ ይህም አንድ ጊዜ ራሱን ይዘጋል፣ በኋላ ሩጫ እንደገና ወደላይ ማንበብ ይችላል።
- `secrets.UI_KIT_SYNC_PR_TOKEN`: በዚህ ማከማቻ ላይ ከይዘት እና የመጎተት ጥያቄዎች ጋር የመዳረሻ መፃፍ ያለው ጥሩ-ጥራጥሬ ማስመሰያ። ነባሪው `GITHUB_TOKEN` እዚህ PRs መፍጠር አይችልም፣ እና የተከፈተው PR CI አያነሳሳም። ያለዚህ ማስመሰያ የስራ ሂደቱ ቅርንጫፉን ብቻ ይገፋፋል.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` የላይኛውን `src/` በዛ ቁርጠኝነት ይገለብጣል (`latest` = the new `v*` tag) ወደ `packages/ui-kit/src`, ነጠላ የተፈቀደውን ለውጥ ይተገበራል (ከአንፃራዊ ማስመጣት የ `.js` ቅጥያ ይጥላል) እና የስራ ቦታ ሥሪቱን በ `packages/ui-kit/package.json` እና `package-lock.json` ወደ ላይኛው ያዘጋጃል። በመቀጠል `git diff packages/ui-kit` ይገምግሙ፣ በአቅራቢዎች፣ መቼቶች፣ ጥንብሮች፣ አጠቃቀም እና የመጨረሻ ነጥብ በሁለቱም ጭብጦች ላይ ያድርጉ፣ `npm run check:ui-kit-snapshot` እና `npm run test:vitest:ui` ን ያሂዱ እና PR ከላይ ባለው የለውጥ ሎግ ይክፈቱ።
