## १. चीजहरू कहाँ छन्

- **किट।** `packages/ui-kit/src` भनेको `packages/ui-kit/UPSTREAM.md` मा पिन गरिएको commit को upstream `src/` को byte-for-byte प्रतिलिपि हो (त्यस फाइलमा license authorization पनि अभिलेखित छ); `PATCHES.md` मा स्थानीय patches सूचीबद्ध छन् (कुनै छैन)। यसलाई build नगरी source का रूपमा प्रयोग गरिन्छ: `next.config.mjs` ले यसलाई transpile गर्छ, र `tsconfig.json` ले `@omniroute/ui-kit` → `packages/ui-kit/src` तथा `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` म्याप गर्छ (`vitest.config.ts` र `vitest.mcp.config.ts` मा पनि यही alias छ)। किटको component लाई यसको subpath (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) बाट import गर्नुहोस्, `@omniroute/ui-kit` barrel मार्फत कहिल्यै होइन: barrel ले प्रत्येक importer मा हरेक component (date picker सहित) तान्छ। किटको stylesheet `src/app/globals.css` मार्फत समावेश हुन्छ (`@import "../../packages/ui-kit/src/ci-styles.css"`, पूर्ण sheet: core `ci-ui.css` र हरेक pattern family सहित)।
- **Tokens।** `packages/ui-kit/src/ci-tokens.css` ले `--ci-*` tokens घोषणा गर्छ; `src/app/globals.css` ले तिनलाई legacy OmniRoute नामहरू (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) मा bridge गर्छ, त्यसैले विद्यमान `var(--color-*)` reads र Tailwind utilities काम गरिरहन्छन्। नयाँ code ले Tailwind utilities (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) वा kit classes प्रयोग गर्छ — hex value कहिल्यै होइन (`tests/unit/design-kit-bridge.test.ts` ले bridge लागू भएको सुनिश्चित गर्छ)। `text-primary` ले `--text-color-primary` मार्फत `--color-primary-ink` मा resolve हुन्छ, त्यसैले primary text पढ्न मिल्ने रहन्छ, जबकि `bg-primary`/`border-primary` ले accent surface कायम राख्छन्: Editions अन्तर्गत यो kit को `--ci-color-accent-active` (light मा गाढा copper `#99562f`, dark मा copper accent) हो; Classic अन्तर्गत light मा lime-800 र dark मा lime accent हो। Chart series ले `--color-chart-1` … `--color-chart-8` प्रयोग गर्छन्, र प्रत्येकसँग text-safe `--color-chart-N-ink` तथा opaque `--color-chart-N-subtle` chip tint हुन्छ, जुन kit series order (`ciChartSeriesOrder`) अनुसार assign गरिन्छ।
- **Themes।** `<html className="ci-theme">` (`src/app/layout.tsx`) ले document लाई kit theme मा opt-in गराउँछ। Preference `light`, `dark` वा `system` हो (`src/shared/constants/appConfig.ts` मा `THEME_CONFIG.defaultTheme = "system"`); `system` ले `prefers-color-scheme` पछ्याउँछ। `src/store/themeStore.ts` को `applyTheme()` (यसको प्रतिबिम्ब `THEME_BOOT_SCRIPT` मा छ, जुन `src/app/layout.tsx` मा inline गरिएको हुन्छ र hydration अघि चल्छ) ले `data-theme="dark"|"light"` सेट गर्छ र `<html>` मा `.dark` class सँगै toggle गर्छ। किटको dark token set `data-theme="dark"` मा आधारित छ (`packages/ui-kit/src/ci-tokens.css`); OmniRoute का आफ्नै dark overrides (`globals.css` को `.dark` block) र legacy Tailwind `dark:` utilities `.dark` class मा आधारित छन्। Accent color presets छैनन्: accent सधैँ kit बाट आउँछ, र पुरानो build बाट persist भएको preset store load हुँदा हटाइन्छ।
- **Palettes।** दुईवटा छन्, दुवै kit बाट (`src/shared/constants/appearancePalette.ts`): `editions`, default, र `classic`। Editions भनेको `<html>` मा kit को `data-ci-appearance="editions"` attribute हो, जसलाई `ci-editions.css` (`ci-ui.css` बाट imported) ले `data-theme` सँग संयोजन गर्छ; Classic भनेको उक्त attribute को अनुपस्थिति हो। Root layout ले attribute server-render गर्छ, त्यसैले केही पनि stored नभएको (वा JS नभएको) visitor ले हरेक surface मा — dashboard, login, `/status`, error pages, `/docs` र PWA — Editions पाउँछ। यो choice theme सँगै उही `theme` store मा persist हुन्छ (`palette`, `setPalette()`, `applyPalette()` `src/store/themeStore.ts` मा) र `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, layout को `<head>` मा inline गरिएको) द्वारा paint अघि लागू हुन्छ; stored palette `"classic"` हुँदा मात्र यसले attribute हटाउँछ; root layout बाहिर रहेको `src/app/global-error.tsx` ले पनि यही store बाट यसलाई लागू गर्छ। `data-ci-appearance` कुनै अन्य element मा नराख्नुहोस्: kit ले यसलाई `html:root:has([data-ci-appearance="editions"])` सँग match गर्छ, त्यसैले एउटा descendant ले सम्पूर्ण document switch गर्नेछ। Editions को `data-ci-editions-variant="landing"` variant marketing pages का लागि हो, dashboard का लागि होइन। Browser chrome: server ले default, Editions, लाई `viewport.themeColor` (प्रत्येक `prefers-color-scheme` का लागि एउटा tag) र web manifest मा render गर्छ — `src/shared/constants/pwaThemeColors.ts` मा रहेको `PWA_THEME_COLORS`, Editions को `--ci-color-background` (`#f3f1e9` / `#11120f`) को एक मात्र mirror, `tests/unit/pwa-theme-colors.test.ts` द्वारा `ci-editions.css` मा pinned छ। त्यसपछि live `<meta name="theme-color">` ले stored palette र mode पछ्याउँछ: `THEME_BOOT_SCRIPT` ले paint अघि tags rewrite गर्छ र theme store का actions ले हरेक परिवर्तनमा त्यसो गर्छन् (`src/shared/utils/themeColorMeta.ts` मा `resolveThemeColor()` / `applyThemeColor()`, `CLASSIC_PAGE_BACKGROUND` kit को `ciTokens` बाट read गरिन्छ)। Explicit light/dark theme ले हरेक tag लाई त्यही mode मा सेट गर्छ; `system` ले प्रत्येक scheme का लागि एउटा color कायम राख्छ। Manifest Editions मै रहन्छ: यो प्रत्येक install का लागि एकपटक fetch हुन्छ, preference बिना। Monaco ले probe (`monacoKitTheme.ts`) बाट आफ्ना colors पढ्छ; Editions अन्तर्गत probe read ले root `data-theme` लाई एउटै synchronous pass का लागि flip गर्छ, किनभने kit ले root बाट Editions light/dark resolve गर्छ।
- **Components (adapters)।** `src/shared/components/index.tsx` ले OmniRoute component API (उही names, default exports र props) कायम राख्छ, र त्यसको पछाडिका primitives kit माथिका adapters हुन्: forms (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), overlays र feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), structure (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) र tables (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`)। Adapter ले kit component लाई subpath बाट import गर्छ र legacy props लाई त्यसमा म्याप गर्छ — उदाहरणका लागि `Button variant="primary"` भनेको kit को `default` button हो (`--ci-button-primary-*`: light मा inverse surface, dark मा यसको `--ci-color-accent-foreground` ink सहितको accent), `danger` भनेको `destructive` हो, र `warning` भनेको `outline` तथा `.ci-button--warning` extension को संयोजन हो। `globals.css` को अन्त्यमा रहेका `.ci-button--warning` र `.ci-badge[data-tone]` rules (`@layer components`) kit classes माथिका OmniRoute extensions हुन्। `tests/unit/ui/adapters/*.test.tsx` ले प्रत्येक adapter लाई pin गर्छ।
- **शेल।** `src/app/(dashboard)/layout.tsx` ले `DashboardLayout` रेंडर गर्छ, जसले
  `src/shared/components/layouts/DashboardShell.tsx` रेंडर गर्छ: किटको `SidebarProvider` / `Sidebar` /

  एलिमेन्ट हो। `src/shared/components/Header.tsx` मा किटको `SidebarTrigger` (शेलको एक मात्र sidebar

## २. नियमहरू

1. लिटरल होइन, टोकनहरू प्रयोग गर्नुहोस्। जानाजानी राखिएका अपवादहरू: सधैँ गाढा रहने कन्सोल टर्मिनल र
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`), लिटरल हेक्स आवश्यक पर्ने कलरहरूका लागि
   किटको स्टाटस प्यालेटको resolved-hex प्रतिरूप। वर्गीकृत प्यालेटहरू अब अपवाद होइनन्:
   तिनीहरू किटका आठवटा चार्ट टोकनहरू (`--color-chart-1..8`, साथै `-ink`/`-subtle`) मा आधारित हुन्छन्,
   किट सिरिजको क्रमअनुसार, `src/shared/utils/categoricalPalette.ts` मार्फत र रुटिङ रणनीतिहरूका लागि

5. टेक्स्ट: किट कम्पोनेन्टहरूमा पास गर्ने लेबलहरूसहित हरेक स्ट्रिङ `useTranslations` बाट आउँछ। नयाँ कुञ्जीहरू `src/i18n/messages/en.json`, `pt-BR.json` र `vi.json` मा राखिन्छन् (भियतनामी प्यारिटी टेस्टले हरेक अङ्ग्रेजी कुञ्जी पिन गर्छ); बाँकी लोकेलाहरू i18n सिङ्कले भर्छन्।

## 4. एडाप्टर थप्ने वा परिवर्तन गर्ने

1. `src/shared/components/index.tsx` को सार्वजनिक API यथावत् राख्नुहोस्: उही export नामहरू, default exportहरू र स्वीकार गरिने propsहरू। पुराना (legacy) propsहरूलाई एडाप्टरभित्रै किटमा म्याप गर्नुहोस् (`Button.tsx` हेर्नुहोस्: `VARIANT_TO_KIT`, `SIZE_TO_KIT`)।
2. किटलाई subpath बाट import गर्नुहोस् (`@omniroute/ui-kit/<component>`)।
3. किटका कमीहरूका workaroundहरू एडाप्टरमै रहन्छन् (वा समाधान स्टाइल सम्बन्धी भए `globals.css` को `@layer components` मा), कहिल्यै `packages/ui-kit/src` मा होइन।
4. `tests/unit/ui/adapters/<name>.test.tsx` थप्नुहोस् वा अपडेट गर्नुहोस्। धेरै callerहरू भएको एडाप्टरको हकमा, परिवर्तनअघि र परिवर्तनपछिको rendered markup तुलना गर्नुहोस् — padding वा wrapper परिवर्तनहरू हरेक स्क्रिनमा फैलिन्छन्।

## 5. किट अद्यावधिक गर्दै

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` मा पिन गरिएको संस्करणलाई अपस्ट्रिम रेपोको सबैभन्दा नयाँ `v*` ट्यागसँग तुलना गर्छ र रिलीज बाहिर हुँदा सिङ्क आदेश छाप्छ।

दैनिक `UI Kit upstream watch` कार्यप्रवाह (`.github/workflows/ui-kit-upstream-watch.yml`) ले उही जाँच चलाउँछ। पिन पछाडि हुँदा, `scripts/ci/ui-kit-sync-pr.sh` एउटा सिंक PR उच्चतम `release/vX.Y.Z` शाखा विरुद्ध, रोलिङ शाखा `chore/ui-kit-sync-latest` मा खुला राख्छ। यो कहिल्यै मर्ज हुँदैन: प्रत्येक किट रिलीजलाई अझै पनि स्थानीय VPS मा भिजुअल जाँच चाहिन्छ। शाखा पुन: निर्माण गरिन्छ जब नयाँ रिलीज बाहिर हुन्छ र अन्यथा एक्लै छोडिन्छ। हातले धकेलिएको कमिट सहितको खुला PR ओभरराइट हुँदैन, र एक PR संस्करणको लागि जुन एक मर्मतकर्ताले अनमर्ज नगरेको नयाँ रिलीज नभएसम्म बन्द रहन्छ।

जब कुनै PR खोल्न सकिँदैन (लक्ष्य रिलीज फ्रिज गरिएको छ, PR ले हातले धकेलिएको छ, PR बन्द गरिएको छ, वा कुनै PR टोकन सेट गरिएको छैन) कार्यप्रवाहले एउटा ट्र्याकिङ मुद्दालाई खुला राख्छ जसले किन भन्छ।

कार्यप्रवाहले दुई रहस्यहरू प्रयोग गर्दछ:

- `secrets.UI_KIT_READ_TOKEN`: निजी अपस्ट्रीम रिपोको लागि पढ्ने मात्र टोकन। जब कार्यप्रवाहले अपस्ट्रीम पढ्न सक्दैन (कुनै टोकन, टोकन जसले काम गर्न रोकेको छ, वा GitHub पहुँचयोग्य छैन) रन हरियो रहन्छ तर चेतावनी लेख्छ र एउटा छुट्टै मुद्दा खुला राख्छ, जुन पछि रनले फेरि अपस्ट्रीम पढ्न सक्छ।
- `secrets.UI_KIT_SYNC_PR_TOKEN`: यस भण्डारमा सामग्री र पुल अनुरोधहरू लेख्न पहुँचको साथमा राम्रो-दाना भएको टोकन। पूर्वनिर्धारित `GITHUB_TOKEN` यहाँ PRs सिर्जना गर्न सक्दैन, र यो खोलिएको PR ले CI ट्रिगर गर्दैन। यो टोकन बिना कार्यप्रवाहले शाखालाई मात्र धक्का दिन्छ।

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` अपस्ट्रिम `src/` त्यो कमिटमा (`latest` = सबैभन्दा नयाँ `v*` ट्याग) लाई `packages/ui-kit/src` मा प्रतिलिपि गर्दछ, एकल अनुमति दिइएको रूपान्तरण लागू गर्दछ (यसले सापेक्ष आयातबाट `.js` प्रत्यय छोड्छ), र कार्यस्थान संस्करणलाई `packages/ui-kit/package.json` र `package-lock.json` मा अपस्ट्रीममा सेट गर्दछ। त्यसपछि: `git diff packages/ui-kit` समीक्षा गर्नुहोस्, प्रदायकहरू, सेटिङहरू, कम्बोहरू, प्रयोग र दुवै थिमहरूमा अन्तिम बिन्दुमा भिजुअल पास गर्नुहोस्, `npm run check:ui-kit-snapshot` र `npm run test:vitest:ui` चलाउनुहोस्, र अपस्ट्रिम चेन्जलगको साथ PR खोल्नुहोस्।

  निर्माण गर्छ), जुन कोरिएको पाठ र आउटलाइनिङ चरणको इनपुट दुवै हो। आधिकारिक आँकडाहरू `<text>` नोडहरूमा
  रहन्छन् (आउटलाइन गरिएपछि अदृश्य, `fill-opacity:0`), जसलाई `check:docs-counts`
  (`scripts/check/check-docs-counts-sync.mjs`) ले पढ्छ; उक्त गेटले पढ्ने रेखाचित्रका पुरानोपन परीक्षणहरूले
  उत्पन्न गरिएको फाइलमा यसका भ्यालिडेटरहरू पनि चलाउँछन्, त्यसैले कोडबाट विचलित भएको आँकडाले परीक्षण
  असफल गराउँछ — जेनेरेटरको सङ्ख्या कहिल्यै होइन, गेटले पढ्ने स्रोत सच्याउनुहोस्।
