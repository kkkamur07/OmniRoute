> **অবস্থা:** ড্যাশবোর্ডটি **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`)-এর ওপর নির্মিত, যা
> ওয়ার্কস্পেস `packages/ui-kit` (`@omniroute/ui-kit`) হিসেবে ভেন্ডর করা হয়েছে; আপস্ট্রিম স্ন্যাপশটটি
> `packages/ui-kit/UPSTREAM.md`-এ পিন করা এবং `npm run check:ui-kit-snapshot` দ্বারা সুরক্ষিত। Light হলো ক্যানোনিক্যাল
> থিম; ডিফল্ট পছন্দ `system`। ডিফল্ট প্যালেটটি কিটের **Editions** রূপ
> (উষ্ণ কাগজসদৃশ নিরপেক্ষ রং এবং কপার অ্যাকসেন্ট `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); সেটিংস →
> রূপ → রঙের প্যালেটে **Classic** বিকল্পটি রয়েছে, যা লাইম অ্যাকসেন্টসহ কিটের বেস টোকেন ব্যবহার করে। UI, ডিসপ্লে এবং কোড টেক্সটের
> একমাত্র ফন্ট ফ্যামিলি হলো Switzer (`--ci-font-ui`; `--ci-font-display` এবং
> `--ci-font-mono` এটিতেই রেজলভ হয়), যা কিট নিজেই সেলফ-হোস্ট করে (`packages/ui-kit/src/ci-fonts.css`,
> `ci-tokens.css` দ্বারা ইমপোর্ট করা)। Switzer-এ অনুপস্থিত লিপিগুলোর জন্য গ্লিফ ধরে ধরে ফলব্যাক প্রয়োগ করা হয় (`src/app/globals.css`):
> সিরিলিক, গ্রিক ও ভিয়েতনামির জন্য Inter এবং কেবল `html[dir="rtl"]`-এর অধীনে আরবি লিপির জন্য Vazirmatn।
> প্রতিটি আইকনই একটি Lucide গ্লিফ।

## 1. জিনিসপত্র কোথায় থাকে

- **কিট।** `packages/ui-kit/src` হলো কমিটে পিন করা upstream `src/`-এর byte-for-byte কপি, যা
  `packages/ui-kit/UPSTREAM.md`-এ উল্লেখ করা আছে (এখানেই লাইসেন্স অনুমোদনও নথিভুক্ত); `PATCHES.md`-এ
  স্থানীয় প্যাচের তালিকা রয়েছে (কোনোটিই নেই)। এটি কোনো build ছাড়াই source হিসেবে ব্যবহৃত হয়:
  `next.config.mjs` এটিকে transpile করে, এবং `tsconfig.json` `@omniroute/ui-kit` →
  `packages/ui-kit/src` এবং `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` ম্যাপ করে
  (`vitest.config.ts` এবং `vitest.mcp.config.ts`-এ একই alias রয়েছে)। কিটের কোনো component-কে তার
  subpath দিয়ে import করুন (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), কখনোই
  `@omniroute/ui-kit` barrel-এর মাধ্যমে নয়: barrel প্রতিটি importer-এর মধ্যে প্রতিটি component
  (date picker-সহ) টেনে আনে। কিটের stylesheet `src/app/globals.css`-এর মাধ্যমে প্রবেশ করে
  (`@import "../../packages/ui-kit/src/ci-styles.css"`, সম্পূর্ণ sheet: core `ci-ui.css` এবং
  প্রতিটি pattern family)।
- **টোকেন।** `packages/ui-kit/src/ci-tokens.css`-এ `--ci-*` token ঘোষণা করা হয়েছে; `src/app/globals.css`
  এগুলোকে পুরোনো OmniRoute নামগুলোর সঙ্গে সংযুক্ত করে (`--color-*`, `--radius-*`,
  `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`), যাতে বিদ্যমান
  `var(--color-*)` read এবং Tailwind utility-গুলো কাজ করতে থাকে। নতুন code-এ Tailwind utility
  (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…)
  অথবা kit class ব্যবহার করুন — কখনোই hex value নয়
  (`tests/unit/design-kit-bridge.test.ts` bridge-টি enforce করে)। `text-primary`
  `--text-color-primary`-এর মাধ্যমে `--color-primary-ink`-এ resolve হয়, তাই primary text পাঠযোগ্য
  থাকে, আর `bg-primary`/`border-primary` accent surface বজায় রাখে: Editions-এ এটি kit-এর
  `--ci-color-accent-active` (light-এ deep copper `#99562f`, dark-এ copper accent); Classic-এ
  light-এ lime-800 এবং dark-এ lime accent। Chart series-গুলো `--color-chart-1` … `--color-chart-8`
  ব্যবহার করে; প্রতিটির একটি text-safe `--color-chart-N-ink` এবং একটি opaque
  `--color-chart-N-subtle` chip tint রয়েছে, যা kit series order (`ciChartSeriesOrder`) অনুযায়ী
  নির্ধারিত।
- **থিম।** `<html className="ci-theme">` (`src/app/layout.tsx`) document-কে kit theme-এ যুক্ত করে।
  preference হলো `light`, `dark` অথবা `system` (`src/shared/constants/appConfig.ts`-এ
  `THEME_CONFIG.defaultTheme = "system"`); `system` `prefers-color-scheme` অনুসরণ করে।
  `src/store/themeStore.ts`-এর `applyTheme()` (`src/app/layout.tsx`-এ inline করা
  `THEME_BOOT_SCRIPT`-এও প্রতিফলিত), hydration-এর আগে চলে এবং একই সঙ্গে
  `data-theme="dark"|"light"` সেট করে ও `<html>`-এর `.dark` class toggle করে। কিটের dark token set
  `data-theme="dark"`-এর ওপর নির্ভর করে (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-এর নিজস্ব
  dark override (`globals.css`-এর `.dark` block) এবং পুরোনো Tailwind `dark:` utility `.dark` class-এর
  ওপর নির্ভর করে। কোনো accent color preset নেই: accent সবসময় kit থেকে আসে, এবং পুরোনো build থেকে
  persisted preset store load হওয়ার সময় বাদ দেওয়া হয়।
- **প্যালেট।** দুটি, উভয়ই kit থেকে (`src/shared/constants/appearancePalette.ts`): default `editions`
  এবং `classic`। Editions হলো `<html>`-এর kit-এর `data-ci-appearance="editions"` attribute, যা
  `ci-editions.css` (`ci-ui.css` দ্বারা imported) `data-theme`-এর সঙ্গে মিলিয়ে প্রয়োগ করে; Classic
  হলো attribute-এর অনুপস্থিতি। Root layout server-side-এ attribute render করে, তাই কিছুই stored না থাকা
  visitor (অথবা JS না থাকা visitor) প্রতিটি surface-এ — dashboard, login, `/status`, error page,
  `/docs` এবং PWA-তে — Editions পায়। পছন্দটি একই `theme` store-এ theme-এর পাশে persisted হয়
  (`palette`, `setPalette()`, `applyPalette()` `src/store/themeStore.ts`-এ) এবং
  `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, layout-এর `<head>`-এ inline করা)
  paint-এর আগে প্রয়োগ করে; stored palette `"classic"` হলেই কেবল attribute সরায়;
  root layout-এর বাইরে থাকা `src/app/global-error.tsx` একই store থেকে এটি প্রয়োগ করে।
  অন্য কোনো element-এ `data-ci-appearance` বসাবেন না: kit এটি
  `html:root:has([data-ci-appearance="editions"])` দিয়ে match করে, তাই একটি descendant পুরো
  document বদলে দেবে। Editions-এর `data-ci-editions-variant="landing"` variant marketing page-এর
  জন্য, dashboard-এর জন্য নয়। Browser chrome: server default, Editions, `viewport.themeColor`-এ
  render করে (`prefers-color-scheme` প্রতি একটি tag) এবং web manifest-এ —
  `src/shared/constants/pwaThemeColors.ts`-এর `PWA_THEME_COLORS`, যা Editions-এর
  `--ci-color-background` (`#f3f1e9` / `#11120f`)-এর একমাত্র mirror এবং
  `tests/unit/pwa-theme-colors.test.ts` দ্বারা `ci-editions.css`-এ pin করা। এরপর live
  `<meta name="theme-color">` stored palette এবং mode অনুসরণ করে: `THEME_BOOT_SCRIPT` paint-এর আগে
  tag-গুলো rewrite করে এবং theme store-এর action-গুলো প্রতিটি পরিবর্তনে তা করে
  (`src/shared/utils/themeColorMeta.ts`-এর `resolveThemeColor()` /
  `applyThemeColor()`, যেখানে kit-এর `ciTokens` থেকে `CLASSIC_PAGE_BACKGROUND` read করা হয়)।
  Explicit light/dark theme প্রতিটি tag-কে সেই mode-এ সেট করে; `system` প্রতি scheme-এর জন্য
  একটি করে colour বজায় রাখে। Manifest Editions-এই থাকে: এটি প্রতি install-এ একবার fetch করা হয়,
  preference ছাড়াই। Monaco একটি probe থেকে তার colour read করে (`monacoKitTheme.ts`);
  Editions-এর অধীনে probe read synchronous pass-এর জন্য root-এর `data-theme` flip করে, কারণ kit
  root থেকে Editions light/dark resolve করে।
- **Components (adapters)।** `src/shared/components/index.tsx` OmniRoute component API
  (একই নাম, default export এবং props) বজায় রাখে, আর এর পেছনের primitive-গুলো kit-এর ওপর তৈরি
  adapter: forms (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`),
  overlays এবং feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`,
  `EmptyState`, `Loading`), structure (`Collapsible`, `CollapsibleSection`, `SegmentedControl`,
  `Breadcrumbs`, `Avatar`) এবং tables (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`,
  `PresetSlider`)। একটি adapter kit component-কে subpath দিয়ে import করে এবং legacy props-কে
  তার ওপর ম্যাপ করে — উদাহরণস্বরূপ, `Button variant="primary"` হলো kit-এর `default` button
  (`--ci-button-primary-*`: light-এ inverse surface, dark-এ তার
  `--ci-color-accent-foreground` ink-সহ accent), `danger` হলো `destructive`, এবং `warning` হলো
  `outline`-এর সঙ্গে `.ci-button--warning` extension। `globals.css`-এর শেষে
  (`@layer components`) থাকা `.ci-button--warning` এবং `.ci-badge[data-tone]` rule-গুলো kit
  class-এর ওপর তৈরি OmniRoute extension। `tests/unit/ui/adapters/*.test.tsx` প্রতিটি adapter-কে
  pin করে।
- **শেল।** `src/app/(dashboard)/layout.tsx` `DashboardLayout` রেন্ডার করে, যা
  `src/shared/components/layouts/DashboardShell.tsx` রেন্ডার করে: কিটের `SidebarProvider` / `Sidebar` /
  `SidebarInset` (`packages/ui-kit/src/sidebar.tsx`), যেখানে OmniRoute-এর নেভিগেশন লজিক রয়েছে
  `src/shared/components/Sidebar.tsx`-এ। `#main-content`-এ যাওয়ার "skip to content" লিংকটি ফোকাসযোগ্য
  প্রথম উপাদান। `src/shared/components/Header.tsx`-এ কিটের `SidebarTrigger` (শেলের একমাত্র sidebar
  toggle), Keak-এর `ProductSwitcher` এবং command-palette opener রয়েছে; `#main-content`-এর ভিতরে কোনো
  কিট `PageHeader` (`.ci-page-header`) মাউন্ট না থাকা অবস্থাতেই এটি route title দেখায়, তাই নিজস্ব
  `PageHeader` থাকা পেজে একটি মাত্র `h1` থাকে। `src/shared/components/CommandPalette.tsx` একটি কিট
  `Dialog`।
- **আইকন।** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) নামটি
  `src/shared/constants/iconMap.ts`-এর `ICON_MAP`-এর মাধ্যমে (স্ক্রিনগুলোতে ব্যবহৃত Material Symbols
  vocabulary) একটি Lucide glyph-এ রিজলভ করে। Material Symbols font এবং package সরিয়ে ফেলা হয়েছে:
  map-এ অনুপস্থিত কোনো নাম একটি নিরপেক্ষ placeholder glyph (`data-icon-missing="true"`) রেন্ডার করে এবং
  production-এর বাইরে console warning লগ করে। `npm run gen:icon-map` ব্যবহৃত কিন্তু map-এ অনুপস্থিত
  নামগুলো প্রিন্ট করে (`tests/unit/icon-map-coverage.test.ts`-এ Lucide icon ছাড়া যেকোনো নামের জন্য

## 5. কিট আপডেট করা হচ্ছে

`npm run check:ui-kit-upstream` আপস্ট্রিম রেপোর নতুন `v*` ট্যাগের সাথে `packages/ui-kit/UPSTREAM.md` এ পিন করা সংস্করণটিকে তুলনা করে এবং যখন একটি রিলিজ বের হয় তখন সিঙ্ক কমান্ড প্রিন্ট করে।

দৈনিক `UI Kit upstream watch` ওয়ার্কফ্লো (`.github/workflows/ui-kit-upstream-watch.yml`) একই চেক চালায়। পিনটি পিছনে থাকাকালীন, `scripts/ci/ui-kit-sync-pr.sh` একটি সিঙ্ক PR সর্বোচ্চ `release/vX.Y.Z` শাখার বিপরীতে, ঘূর্ণায়মান শাখা `chore/ui-kit-sync-latest` এ খোলা রাখে। এটি কখনই একত্রিত হয় না: প্রতিটি কিট প্রকাশের এখনও স্থানীয় VPS এ একটি ভিজ্যুয়াল চেক প্রয়োজন। একটি নতুন রিলিজ বের হলে এবং অন্যথায় একা রেখে দিলে শাখাটি পুনর্নির্মাণ করা হয়। হাত দ্বারা ঠেলে কমিট সহ একটি খোলা PR ওভাররাইট করা হয় না, এবং একটি সংস্করণের জন্য একটি PR যা একটি রক্ষণাবেক্ষণকারী বন্ধ অবিকৃত একটি নতুন প্রকাশ না হওয়া পর্যন্ত বন্ধ থাকে।

যখন কোন PR খোলা যায় না (টার্গেট রিলিজ হিমায়িত করা হয়েছে, PR হাত দিয়ে ঠেলে কমিট করেছে, PR বন্ধ ছিল, বা কোন PR টোকেন সেট করা নেই) ওয়ার্কফ্লো একটি ট্র্যাকিং সমস্যা খোলা রাখে যা বলে কেন।

কর্মপ্রবাহ দুটি গোপন ব্যবহার করে:

- `secrets.UI_KIT_READ_TOKEN`: ব্যক্তিগত আপস্ট্রিম রেপোর জন্য একটি পঠনযোগ্য টোকেন। যখন ওয়ার্কফ্লো আপস্ট্রিম পড়তে পারে না (কোন টোকেন, একটি টোকেন যা কাজ করা বন্ধ করে দেয়, বা GitHub পৌঁছানো যায় না) রানটি সবুজ থাকে কিন্তু একটি সতর্কতা লেখে এবং একটি পৃথক সমস্যা খোলা রাখে, যা পরে আবার আপস্ট্রিম পড়তে পারে একবার নিজেই বন্ধ হয়ে যায়।
- `secrets.UI_KIT_SYNC_PR_TOKEN`: একটি সূক্ষ্ম দানাদার টোকেন এই রিপোজিটরিতে বিষয়বস্তু এবং পুল রিকোয়েস্ট লেখার অ্যাক্সেস সহ। ডিফল্ট `GITHUB_TOKEN` এখানে PRs তৈরি করতে পারে না, এবং এটি খোলা একটি PR CI ট্রিগার করবে না। এই টোকেন ছাড়া কর্মপ্রবাহ শুধুমাত্র শাখা ধাক্কা.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` সেই প্রতিশ্রুতিতে আপস্ট্রিম `src/` কপি করে (`latest` = নতুন `v*` ট্যাগ) `packages/ui-kit/src` এ, একক অনুমোদিত রূপান্তর প্রয়োগ করে (এটি আপেক্ষিক আমদানি থেকে `.js` প্রত্যয়টি ড্রপ করে), এবং `packages/ui-kit/package.json` এবং `package-lock.json` তে ওয়ার্কস্পেস সংস্করণ আপস্ট্রিমে সেট করে। তারপর: `git diff packages/ui-kit` পর্যালোচনা করুন, উভয় থিমে সরবরাহকারী, সেটিংস, কম্বোস, ব্যবহার এবং এন্ডপয়েন্টের উপর একটি ভিজ্যুয়াল পাস করুন, `npm run check:ui-kit-snapshot` এবং `npm run test:vitest:ui` চালান এবং আপস্ট্রিম চেঞ্জলগ দিয়ে PR খুলুন।

  টেক্সট রঙের জন্য WCAG AA-ও পরীক্ষা করে; একমাত্র ব্যতিক্রম, হালকা `warn`, হলো কিটের সতর্কতা-রঙকে 10 % গাঢ়
  করা, কারণ কিটের মানটি ক্যানভাসে 4.46:1) এবং কিটের টাইপ স্কেলে (`ci-tokens.css`) টেক্সটের ভূমিকাগুলো
  নির্ধারণ করে: সবকিছুর জন্য কিটের ওয়েট (400/500/600, ডিসপ্লের ক্ষেত্রে 500) ও ট্র্যাকিংসহ Switzer,
  শুধু কোডের ভূমিকাগুলো (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) ব্যতিক্রম; এগুলো
  IBM Plex Mono এবং কেবল কমান্ড, URL, আইডেন্টিফায়ার ও টার্মিনাল স্ক্রিনের জন্য ব্যবহৃত হয়।
  হালকা মানগুলো ফাইলের ভেতরে `:root`-এ এবং গাঢ় মানগুলো `prefers-color-scheme: dark`-এর পেছনে থাকে, ফলে
  প্রতিটি ছবি GitHub-এ দর্শকের স্কিম অনুসরণ করে।
- **ফন্ট।** GitHub Markdown কোনো CSS বহন করে না এবং camo প্রক্সি সব বাহ্যিক ফেচ ব্লক করে, তাই কিটের টাইপ
  ফাইলের ভেতরেই বহন করতে হয়। প্রতিটি জেনারেটরের শেষ ধাপ `scripts/docs/readme-outline.mjs`, HarfBuzz দিয়ে
  Switzer ভূমিকাগুলো শেপ করে এবং সেগুলোকে ভেক্টর আউটলাইন (`<defs>` পাথ ও `<use>`) হিসেবে আঁকে; Switzer-এ
  অনুপস্থিত তীর ও জ্যামিতিক প্রতীকগুলো তার নিজস্ব মেট্রিক অনুযায়ী আঁকা হয়। আউটলাইন, কখনোই এম্বেড করা ফন্ট
  নয়: Switzer-এর লাইসেন্স (`packages/ui-kit/src/fonts/FFL.txt`) লিখিত সম্মতি ছাড়া সাবসেটিং ও ফরম্যাট
  রূপান্তর নিষিদ্ধ করে এবং ভেক্টর অঙ্কনের অনুমতি দেয়, তাই কোনো Switzer `@font-face` বা `data:` URI পুনরায়
  যোগ করবেন না। একটি ফাইলে যে একমাত্র ফন্টটি থেকে যায়, তা হলো বাস্তব কোড টেক্সট হিসেবে থেকে যাওয়া অংশের
  জন্য OFL IBM Plex Mono সাবসেট (`scripts/docs/readme-fonts.mjs`), যা ওই অক্ষরগুলো থেকে তৈরি; এম্বেড করা যায়
  না এমন কোনো গ্লিফ পাওয়া গেলে এটি ত্রুটি ছুড়ে দেয়।
- **পুনরায় জেনারেট করুন।** `npm run docs:readme-diagrams` README-এর ক্রম অনুযায়ী বারোটিই পুনরায় লেখে এবং
  প্রতিটি ফাইলের আকারসহ একটি করে লাইন প্রিন্ট করে। একটি একক জেনারেটরও নিজে চালানো যায়
  (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget`-এর জন্য `node --import tsx/esm` প্রয়োজন,
  কারণ এর পরিসংখ্যান `open-sse/config/freeModelCatalog.ts`-এর লাইভ ক্যাটালগ লোডার থেকে আসে; ক্যাটালগ
  পরিবর্তনের CI ফলাফল `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`-এ রয়েছে)। জেনারেটর ও SVG
  একসঙ্গে কমিট করুন।
- **প্রমাণ।** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` একটি ফাইলকে GitHub যেভাবে পরিবেশন করে
  সেভাবে রেন্ডার করে (একটি `<img>` ট্যাগ, camo-এর `Content-Security-Policy`, `image/svg+xml`), একটি হালকা ও
  একটি গাঢ় ফ্রেম ক্যাপচার করে এবং পেজটি যতগুলো বাহ্যিক ফন্ট অনুরোধ করেছে তা রিপোর্ট করে (অবশ্যই 0 হতে হবে)।
- **বাজেট।** প্রতিটি ফাইল 200 KB-এর নিচে (প্রতিটি স্টেলনেস টেস্ট এটি যাচাই করে); যেকোনো README ছবির জন্য
  500 KB হলো কঠোর সর্বোচ্চ সীমা (SVG studio ভ্যালিডেটরের নিয়ম)।
- **কপি অপরিবর্তিত, সংখ্যা গেট থেকে।** রিব্র্যান্ডে টাইপ ও প্যালেট বদলেছে, শব্দ নয়: প্রতিটি জেনারেটর তার
  ডায়াগ্রামের কপি একটি `*_COPY` কনস্ট্যান্টে বহন করে (অথবা লাইভ ক্যাটালগ থেকে তৈরি করে), যা একই সঙ্গে
  আঁকা টেক্সট এবং আউটলাইনিং ধাপের ইনপুট। প্রামাণ্য পরিসংখ্যান `<text>` নোডে থাকে (আউটলাইন করার পর অদৃশ্য,
  `fill-opacity:0`), যা `check:docs-counts`
  (`scripts/check/check-docs-counts-sync.mjs`) পড়ে; গেট যে ডায়াগ্রামগুলো পড়ে, সেগুলোর স্টেলনেস টেস্টও
  জেনারেট করা ফাইলে এর ভ্যালিডেটরগুলো চালায়, ফলে কোনো পরিসংখ্যান কোড থেকে বিচ্যুত হলে টেস্ট ব্যর্থ হয় —
  গেট যে উৎস পড়ে সেটিই ঠিক করুন, জেনারেটরের সংখ্যাটি কখনো নয়।
