> **ステータス:** ダッシュボードは **Keak CI UI Kit**（`@keak/cheaper-inference-ui-kit`）を基盤としており、
> ワークスペース `packages/ui-kit`（`@omniroute/ui-kit`）としてベンダリングされています（アップストリームのスナップショットは
> `packages/ui-kit/UPSTREAM.md` に固定され、`npm run check:ui-kit-snapshot` によって保護されています）。Light が標準
> テーマであり、デフォルト設定は `system` です。デフォルトのパレットは、このキットの **Editions** アピアランス
> （温かみのある紙のようなニュートラルカラーと、カッパーのアクセント `#e5ac82`、`packages/ui-kit/src/ci-editions.css`）です。Settings →
> Appearance → Color palette では、ライムのアクセントを持つキットの基本トークンである **Classic** を選択できます。Switzer は
> UI、ディスプレイ、コードテキストのすべてに使用される唯一のフォントファミリーです（`--ci-font-ui`。`--ci-font-display` と
> `--ci-font-mono` もこれに解決されます）。フォントはキット自体によってセルフホストされています（`packages/ui-kit/src/ci-fonts.css`。
> `ci-tokens.css` からインポートされます）。Switzer に含まれない文字体系は、グリフ単位でフォールバックされます（`src/app/globals.css`）。
> キリル文字、ギリシャ文字、ベトナム語には Inter が使用され、アラビア文字には `html[dir="rtl"]` の場合に限り Vazirmatn が使用されます。
> すべてのアイコンは Lucide のグリフです。

## 1. 各要素の場所

- **キット。** `packages/ui-kit/src` は、`packages/ui-kit/UPSTREAM.md` に記録されたコミットにおける上流の `src/` のバイト単位の完全なコピーです（同ファイルにはライセンス許諾も記録されています）。ローカルパッチは `PATCHES.md` に一覧化されています（なし）。ビルドなしでソースとして使用されます。`next.config.mjs` がこれをトランスパイルし、`tsconfig.json` は `@omniroute/ui-kit` → `packages/ui-kit/src`、`@omniroute/ui-kit/*` → `packages/ui-kit/src/*` をマッピングします（`vitest.config.ts` と `vitest.mcp.config.ts` にも同じエイリアスがあります）。キットのコンポーネントはサブパス（`@omniroute/ui-kit/table`、`@omniroute/ui-kit/page-header`…）でインポートし、`@omniroute/ui-kit` のバレル経由では決してインポートしないでください。バレルは日付ピッカーを含むすべてのコンポーネントを各インポーターに取り込みます。キットのスタイルシートは `src/app/globals.css`（`@import "../../packages/ui-kit/src/ci-styles.css"`。コアの `ci-ui.css` とすべてのパターンファミリーを含む完全なシート）から読み込まれます。
- **トークン。** `packages/ui-kit/src/ci-tokens.css` は `--ci-*` トークンを宣言します。`src/app/globals.css` はそれらを従来の OmniRoute 名（`--color-*`、`--radius-*`、`--font-sans`/`--font-mono`、`--table-*`、`--orch-status-*`、`--color-fd-*`）にブリッジするため、既存の `var(--color-*)` の読み取りと Tailwind ユーティリティは引き続き機能します。新しいコードでは Tailwind ユーティリティ（`bg-surface`、`text-text-muted`、`border-border`、`text-success`、`bg-success-bg`、`bg-chart-1`…）またはキットのクラスを使用し、16進数値は決して使用しないでください（`tests/unit/design-kit-bridge.test.ts` がこのブリッジを強制します）。`text-primary` は `--text-color-primary` を通じて `--color-primary-ink` に解決されるため、プライマリテキストは読みやすいままです。一方、`bg-primary`/`border-primary` はアクセントサーフェスを維持します。Editions ではキットの `--ci-color-accent-active`（ライトでは濃い銅色の `#99562f`、ダークでは銅色のアクセント）、Classic ではライトの lime-800、ダークの lime アクセントになります。チャート系列では `--color-chart-1` … `--color-chart-8` を使用します。各系列にはテキストに安全な `--color-chart-N-ink` と、不透明な `--color-chart-N-subtle` チップの色合いがあり、キットの系列順（`ciChartSeriesOrder`）に従って割り当てられます。
- **テーマ。** `<html className="ci-theme">`（`src/app/layout.tsx`）によってドキュメントがキットテーマにオプトインします。設定値は `light`、`dark`、`system` のいずれかです（`src/shared/constants/appConfig.ts` の `THEME_CONFIG.defaultTheme = "system"`。`system` は `prefers-color-scheme` に従います）。`src/store/themeStore.ts` の `applyTheme()`（`src/app/layout.tsx` にインライン化された `THEME_BOOT_SCRIPT` にも反映され、ハイドレーション前に実行されます）は、`data-theme="dark"|"light"` を設定し、`<html>` の `.dark` クラスを同時に切り替えます。キットのダークトークンセットは `data-theme="dark"`（`packages/ui-kit/src/ci-tokens.css`）をキーとします。OmniRoute 独自のダーク上書き（`globals.css` の `.dark` ブロック）と、従来の Tailwind `dark:` ユーティリティは `.dark` クラスをキーとします。アクセントカラーのプリセットはありません。アクセントは常にキットから取得され、以前のビルドで保存されたプリセットはストアの読み込み時に破棄されます。
- **パレット。** 2種類あり、どちらもキット由来です（`src/shared/constants/appearancePalette.ts`）。デフォルトの `editions` と `classic` です。Editions は `<html>` のキットの `data-ci-appearance="editions"` 属性であり、`ci-ui.css` にインポートされた `ci-editions.css` がこれを `data-theme` と組み合わせます。Classic はこの属性がない状態です。ルートレイアウトはこの属性をサーバーレンダリングするため、何も保存されていない訪問者（または JavaScript がない訪問者）にも、ダッシュボード、ログイン、`/status`、エラーページ、`/docs`、PWA のすべてのサーフェスで Editions が適用されます。選択内容はテーマと同じ `theme` ストア（`palette`、`setPalette()`、`src/store/themeStore.ts` の `applyPalette()`）に保存され、`THEME_BOOT_SCRIPT`（`src/shared/utils/themeBootScript.ts`。レイアウトの `<head>` にインライン化）によって描画前に適用されます。このスクリプトは、保存されたパレットが `"classic"` の場合にのみ属性を削除します。ルートレイアウトの外部にある `src/app/global-error.tsx` では、同じストアからこの属性を適用します。`data-ci-appearance` を他の要素に設定しないでください。キットはこの属性を `html:root:has([data-ci-appearance="editions"])` として照合するため、子孫要素が1つあるだけでドキュメント全体が切り替わります。Editions の `data-ci-editions-variant="landing"` バリアントはマーケティングページ用であり、ダッシュボード用ではありません。ブラウザーのUIについては、サーバーがデフォルトの Editions を `viewport.themeColor`（`prefers-color-scheme` ごとに1つのタグ）と Web マニフェストにレンダリングします。`src/shared/constants/pwaThemeColors.ts` の `PWA_THEME_COLORS` は Editions の `--ci-color-background`（`#f3f1e9` / `#11120f`）を唯一ミラーするもので、`tests/unit/pwa-theme-colors.test.ts` により `ci-editions.css` に固定されています。その後、実際の `<meta name="theme-color">` は保存されたパレットとモードに従います。`THEME_BOOT_SCRIPT` は描画前にタグを書き換え、テーマストアのアクションは変更のたびにこれを実行します（`src/shared/utils/themeColorMeta.ts` の `resolveThemeColor()` / `applyThemeColor()`。`CLASSIC_PAGE_BACKGROUND` はキットの `ciTokens` から読み取られます）。明示的な light/dark テーマではすべてのタグがそのモードに設定され、`system` ではスキームごとに1色が維持されます。マニフェストは Editions のままです。インストールごとに一度だけ取得され、設定値は反映されません。Monaco はプローブ（`monacoKitTheme.ts`）から色を読み取ります。Editions では、キットがルートの `data-theme` から Editions のライト/ダークを解決するため、プローブの読み取り時にルートの `data-theme` を1回の同期パスの間だけ反転させます。
- **コンポーネント（アダプター）。** `src/shared/components/index.tsx` は OmniRoute のコンポーネントAPI（同じ名前、デフォルトエクスポート、props）を維持し、その背後のプリミティブはキット上のアダプターです。フォーム（`Button`、`Input`、`Textarea`、`Checkbox`、`Select`、`Toggle`、`Badge`、`Card`）、オーバーレイとフィードバック（`Modal`/`ConfirmModal`、`Tooltip`/`InfoTooltip`、`NotificationToast`、`EmptyState`、`Loading`）、構造（`Collapsible`、`CollapsibleSection`、`SegmentedControl`、`Breadcrumbs`、`Avatar`）、テーブル（`DataTable`、`FilterBar`、`ColumnToggle`、`FilterPills`、`PresetSlider`）が含まれます。アダプターはキットのコンポーネントをサブパスでインポートし、従来の props をそれにマッピングします。たとえば `Button variant="primary"` はキットの `default` ボタン（`--ci-button-primary-*`。ライトでは反転サーフェス、ダークでは `--ci-color-accent-foreground` のインクを備えたアクセント）であり、`danger` は `destructive`、`warning` は `outline` と `.ci-button--warning` 拡張の組み合わせです。`globals.css` の末尾にある `.ci-button--warning` と `.ci-badge[data-tone]` のルール（`@layer components`）は、キットのクラス上に構築された OmniRoute の拡張です。`tests/unit/ui/adapters/*.test.tsx` が各アダプターを固定します。
- **シェル。** `src/app/(dashboard)/layout.tsx` は `DashboardLayout` をレンダリングし、それが
  `src/shared/components/layouts/DashboardShell.tsx` をレンダリングします。このシェルはキットの
  `SidebarProvider` / `Sidebar` / `SidebarInset`（`packages/ui-kit/src/sidebar.tsx`）で構成され、
  OmniRoute のナビゲーションロジックは `src/shared/components/Sidebar.tsx` にあります。「コンテンツへスキップ」リンク（`#main-content` へのリンク）が最初のフォーカス可能な要素です。`src/shared/components/Header.tsx` には、シェル唯一のサイドバー切り替えとしてキットの `SidebarTrigger`、Keak の `ProductSwitcher`、コマンドパレットの起動ボタンがあります。ルートタイトルは、`#main-content` 内にキットの `PageHeader`（`.ci-page-header`）がマウントされていない場合にのみ表示されるため、独自の `PageHeader` を持つページでは `h1` が1つになります。`src/shared/components/CommandPalette.tsx` はキットの `Dialog` です。
- **アイコン。** `<Icon name="material_name">`（`src/shared/components/Icon.tsx`）は、画面で使用される Material Symbols の語彙に基づく名前を、`src/shared/constants/iconMap.ts` の `ICON_MAP` を通じて Lucide のグリフに解決します。Material Symbols のフォントとパッケージは削除されています。マップにない名前は、ニュートラルなプレースホルダーグリフ（`data-icon-missing="true"`）をレンダリングし、本番環境以外ではコンソール警告を記録します。`npm run gen:icon-map` は、使用中でマップにない名前を出力します（`tests/unit/icon-map-coverage.test.ts` は Lucide アイコンのない名前があると失敗し、`tests/unit/icon-map-object-values.test.ts` はルックアップオブジェクトに保存された名前を対象とします）。`scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` は、リテラルの `<span className="material-symbols-outlined">` スパンを `<Icon>` に書き換えます。
- **ブランド。** `src/shared/components/OmniRouteLogo.tsx` はキットをラップします。デフォルトエクスポートの `OmniRouteLogo` は `ProductIcon product="omniroute" variant="glyph"`（インライン SVG、`basePath` に安全）をレンダリングし、`OmniRouteLockup` は `ProductLockup product="omniroute"`（アクセシブル名は「Keak OmniRoute」）をレンダリングします。ホワイトラベル事業者の場合は、独自の `name`/`logoSrc` をレンダリングします。プロダクトスイッチャーの遷移先は `src/shared/constants/keakProducts.ts`（`KEAK_PRODUCT_LINKS`、`KEAK_ACTIVE_PRODUCT`）にあります。スタンドアロン画面 — `src/app/login/page.tsx`、`src/app/status/page.tsx`、`src/app/maintenance/page.tsx`、`src/app/offline/page.tsx`、`src/app/not-found.tsx`、`src/shared/components/ErrorPageScaffold.tsx` — にはロックアップが表示されます。`tests/unit/brand-pages-static.test.ts` がこれを保証します。

## 2. 規則

1. トークンを使用し、リテラルは使用しない。意図的に残されている例外は、常にダークなコンソールターミナルと
   `STATUS_HEX`（`src/shared/constants/statusColors.ts`）、およびリテラルの 16 進数が必要な呼び出し元向けの
   キットのステータスパレットを解決した 16 進数ミラーです。カテゴリーパレットも、もはや例外ではありません。
   キットの 8 つのチャートトークン（`--color-chart-1..8` と `-ink`/`-subtle`）を使用し、
   `src/shared/utils/categoricalPalette.ts` 経由でキットの系列順に並べます。ルーティング戦略では
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` を使用します。ReactFlow のエッジとオーケストレーション
   キャンバスは、テーマに対応した `--orch-status-*` 変数（`src/shared/components/flow/edgeStyles.ts`）を読み取ります。
2. `packages/ui-kit/src` を手動で変更しないでください。`scripts/dev/sync-ui-kit.sh <commit>` で同期します。
   pre-commit ゲートの `npm run check:ui-kit-snapshot`（`.husky/pre-commit`）は、固定された upstream
   commit と異なるバイトが 1 つでもあると失敗します（upstream クローンである
   `UI_KIT_CLONE` または `_references/cheaper-inference-ui-kit` が存在しない場合は、警告を出してスキップします）。
   キットに不足しているものがある場合は、アダプターまたは画面側で回避し、upstream に追加を依頼してください。
3. キットのテキストのデフォルトは英語です（`label = "Loading"`、`loadingLabel = "Loading table"` など）。
   キットコンポーネントがテキストを表示する場合は、必ず `useTranslations(...)` から翻訳済み文字列を渡してください。
4. Tailwind のユーティリティはキットコンポーネントのクラスより優先されます（キットは
   `@layer theme, base, components, utilities` を宣言しており、そのルールは `components` にあります）。
   ユーティリティはキットコンポーネントの色を変更するためではなく、スペーシングとレイアウトに使用してください。
5. 見出しには、ページタイトルとセクションタイトルに `.ci-heading` を使用し、エラーページのステータスコードのような
   大きく余白の多いディスプレイテキストにのみ `.ci-dashboard-display` を使用します。どちらも Switzer を使用します。
6. `tests/unit/dashboard-kit-sweep.test.ts` はキットの採用状況を検査します。`src/app` または
   `src/shared/components` 内に Material のリガチャ用 span がないこと、ダッシュボードツリー
   （`src/app/(dashboard)` と `src/shared/components`）内に生の `<select>`、`<textarea>`、`<table>` がないこと、
   および記載された例外（`Select` アダプターのネイティブ分岐と `RequestLoggerDetail`）以外に手作りの
   `role="dialog"` がないことを確認します。そこにあるすべての生の `<button>` または `<input>` には、
   その直前 3 行以内に理由を含む `kit-exception:` コメントが必要です。パレットの色相と `dark:` バリアントは、
   テストが列挙するファイル内でのみ使用できます。
7. PR 前に、両方のテーマと 390 px のビューポートを確認してください（スクリーンショット）。
   `tests/e2e/a11y.spec.ts` は axe を実行します。

## 3. 画面の追加

1. ページはキットの `PageHeader`（`@omniroute/ui-kit/page-header`、ダッシュボード内では
   `compact`）で開始する — タイトル、説明、`actions`。シェルヘッダーはこれにより自身の
   タイトルを表示しなくなる。
2. コントロールは `@/shared/components`（アダプター）から構築し、アダプターが存在しない
   場所ではサブパス経由でキットコンポーネントを使用する（`Table`/`TableScrollArea`/
   `DataTableShell`、`Field`、`Alert`、`Tabs`、`RadioGroup`、`Slider` など）。
3. アイコン: `<Icon name="…" />`。新しい名前は、意味的に対応する Lucide コンポーネントと
   ともに `ICON_MAP` に追加する。`npm run gen:icon-map` でまだ不足している名前を一覧できる。
4. 色: セマンティックユーティリティ（`text-success`、`bg-warning-bg`、`border-border` など）と、
   チャート系列には `var(--color-chart-N)` を使う。hex 値や、色を繰り返すだけの `dark:`
   バリアントは使わない。
5. テキスト: キットコンポーネントに渡すラベルを含むすべての文字列は `useTranslations` から
   取得する。新しいキーは `src/i18n/messages/en.json`、`pt-BR.json`、`vi.json` に追加する
   （ベトナム語のパリティテストがすべての英語キーをピン留めする）。他のロケールは i18n 同期で
   補完される。
6. PR の前にガードを実行する: `tests/unit/dashboard-kit-sweep.test.ts`、
   `tests/unit/icon-map-coverage.test.ts`、`tests/unit/icon-map-object-values.test.ts`、
   `npm run check:dashboard-typecheck`（`iconMap.ts` の重複インポートを検出できる唯一の
   チェック）、`npm run check:ui-icu`、およびその画面自体のテスト。

## 4. アダプターの追加・変更

1. `src/shared/components/index.tsx` の公開 API を維持すること:エクスポート名、デフォルトエクスポート、
   受け付ける props を同一に保つ。レガシー props はアダプター内でキットの props にマッピングする(`Button.tsx` の
   `VARIANT_TO_KIT`、`SIZE_TO_KIT` を参照)。
2. キットはサブパスでインポートする(`@omniroute/ui-kit/<component>`)。
3. キットの不足部分に対する回避策はアダプター内に置く(修正がスタイルである場合は `globals.css` の
   `@layer components`)。`packages/ui-kit/src` には決して置かない。
4. `tests/unit/ui/adapters/<name>.test.tsx` を追加または更新すること。呼び出し元の多いアダプターでは、
   変更前後でレンダリングされるマークアップを比較すること —— パディングやラッパーの変更はすべての画面に波及する。

## 5. キットのアップデート

`npm run check:ui-kit-upstream` 、 `packages/ui-kit/UPSTREAM.md`に固定されているバージョンとアップストリーム リポジトリの最新の`v*`タグを比較し、リリースがリリースされると同期コマンドを出力します。

毎日の`UI Kit upstream watch`ワークフロー (`.github/workflows/ui-kit-upstream-watch.yml`) は同じチェックを実行します。ピンが後ろにある間、 `scripts/ci/ui-kit-sync-pr.sh`ローリング ブランチ`chore/ui-kit-sync-latest`上の最上位の`release/vX.Y.Z`ブランチに対して 1 つの同期PRを開いたままにします。マージは決して行われません。すべてのキット リリースでは、引き続きローカルVPSでの視覚的なチェックが必要です。新しいリリースがリリースされるとブランチは再構築され、それ以外の場合はそのまま残されます。手動でコミットがプッシュされたオープンなPR上書きされず、メンテナがマージされずに閉じたバージョンのPR 、新しいリリースまで閉じられたままになります。

PRを開くことができない場合 (ターゲット リリースがフリーズしている、 PR手動でプッシュされたコミットがある、 PRが閉じられている、またはPRトークンが設定されていない)、ワークフローはその理由を示す 1 つの追跡問題を未解決のままにします。

ワークフローでは 2 つのシークレットを使用します。

- `secrets.UI_KIT_READ_TOKEN`: プライベート アップストリーム リポジトリの読み取り専用トークン。ワークフローがアップストリームを読み取ることができない場合 (トークンがない、トークンが機能を停止している、またはGitHubに到達できない)、実行は緑色のままですが、警告が書き込まれ、別の 1 つの問題が開いたままになります。後の実行で再びアップストリームを読み取ることができると、問題は自動的に閉じられます。
- `secrets.UI_KIT_SYNC_PR_TOKEN`: コンテンツおよびプルリクエストの書き込みアクセスを持つ、このリポジトリ上のきめ細かいトークン。デフォルトの`GITHUB_TOKEN`ここでPRsを作成できず、開かれたPR CIをトリガーしません。このトークンがないと、ワークフローはブランチをプッシュするだけです。

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]`そのコミット時に上流の`src/` (`latest` =最新の`v*`タグ) を`packages/ui-kit/src`にコピーし、単一の許可された変換を適用し (相対インポートから`.js`サフィックスを削除します)、 `packages/ui-kit/package.json`および`package-lock.json`のワークスペースのバージョンを上流のバージョンに設定します。次に、 `git diff packages/ui-kit`を確認し、両方のテーマでプロバイダー、設定、コンボ、使用法、およびエンドポイントのビジュアルパスを実行し、 `npm run check:ui-kit-snapshot`と`npm run test:vitest:ui`を実行して、アップストリームの変更ログでPR開きます。

## 6. README の図

ルートの `README.md` に埋め込まれている 12 個の図（`docs/diagrams/*.svg`）は、静的画像にキットを適用したものであり、手作業で描かれたものではなく生成されています。`scripts/docs/gen-readme-*.mjs` に 13 個のジェネレーターファイル
（12 個の図に加えて `gen-readme-diagrams.mjs` ドライバー）があり、
`tests/unit/docs/readme-*-svg.test.ts` には図ごとに 1 つ、合計 12 個の陳腐化テストがあります。各テストは、コミット済みファイルと対応する
ジェネレーターの出力をバイト単位で比較します（ジョブ `test-unit`）。

- **トークン。** `scripts/docs/readme-diagram-theme.mjs` は Editions パレット（デフォルトの外観）を
  `packages/ui-kit/src/ci-editions.css` からコピーします（
  `tests/unit/docs/readme-diagram-theme.test.ts` によりそのファイルに固定されています。このテストは、両方の配色におけるすべてのサーフェス上の各テキスト色について WCAG AA への準拠も確認します。唯一の例外であるライトテーマの `warn` は、キットの値がキャンバス上で 4.46:1 であるため、キットの警告色を 10 % 暗くしたものです）。また、キットのタイプスケール（`ci-tokens.css`）に基づいてテキストの役割を定義します。コード用の役割（`.cmd`、`.term`、`.term-lg`、`.mono`、`.mono-sm`、`.mono-xs`）を除き、すべてにキットのウェイト（400/500/600、ディスプレイは 500）とトラッキングを使用した Switzer が適用されます。コード用の役割には IBM Plex Mono が使われ、コマンド、URL、識別子、ターミナル画面にのみ使用されます。
  ライトテーマの値は `:root` に、ダークテーマの値はファイル内の `prefers-color-scheme: dark` の後ろに配置されているため、各画像は GitHub 上で閲覧者の配色に従います。
- **フォント。** GitHub Markdown には CSS が含まれず、camo プロキシはすべての外部フェッチをブロックするため、キットの書体をファイル内に含める必要があります。各ジェネレーターの最終ステップである `scripts/docs/readme-outline.mjs` は、HarfBuzz を使用して Switzer の各役割をシェーピングし、ベクターアウトライン（`<defs>` のパスと `<use>`）として描画します。Switzer にない矢印と幾何学記号は、Switzer 独自のメトリクスに基づいて描画されます。埋め込みフォントではなく、必ずアウトラインを使用してください。Switzer のライセンス（`packages/ui-kit/src/fonts/FFL.txt`）では、書面による同意なしでのサブセット化と形式変換を禁止する一方、ベクター描画は許可されています。そのため、Switzer の `@font-face` や `data:` URI を再導入しないでください。ファイル内に残る唯一のフォントは、実際のコードテキストとして残る部分に使用される OFL ライセンスの IBM Plex Mono サブセット
  （`scripts/docs/readme-fonts.mjs`）で、該当する文字から構築されます。埋め込めないグリフがある場合は例外が発生します。
- **再生成。** `npm run docs:readme-diagrams` は、README の順序ですべての 12 ファイルを書き換え、ファイルごとにサイズを 1 行出力します。個別のジェネレーターを単独で実行することもできます（`node scripts/docs/gen-readme-<name>.mjs`）。
  `free-tier-budget` の数値は
  `open-sse/config/freeModelCatalog.ts` のライブカタログローダーから取得されるため、`node --import tsx/esm` が必要です。カタログ変更による CI への影響については、
  `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` を参照してください。ジェネレーターと SVG は一緒にコミットしてください。
- **検証。** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` は、GitHub が配信する方法
  （`<img>` タグ、camo の `Content-Security-Policy`、`image/svg+xml`）でファイルをレンダリングし、ライトテーマとダークテーマのフレームをキャプチャして、ページが行った外部フォントリクエスト数を報告します（0 でなければなりません）。
- **容量。** 1 ファイルあたり 200 KB 未満です（各陳腐化テストでアサートされます）。README
  画像のハード上限は 500 KB です（SVG studio バリデーターのルール）。
- **文言は変更せず、数値はゲートから取得。** リブランドで変更されたのは書体とパレットであり、文言ではありません。各ジェネレーターは図の文言を `*_COPY` 定数として保持するか、ライブカタログから構築します。この文言は、描画されるテキストであると同時に、アウトライン化ステップへの入力でもあります。正式な数値は `<text>` ノード内に保持され（アウトライン化後は不可視、`fill-opacity:0`）、`check:docs-counts`
  （`scripts/check/check-docs-counts-sync.mjs`）によって読み取られます。そのゲートが読み取る図の陳腐化テストでは、生成されたファイルに対してゲートのバリデーターも実行されるため、数値がコードから乖離するとテストが失敗します。ジェネレーター内の数値ではなく、必ずゲートが読み取るソースを修正してください。
