> **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) əsasında qurulub. İşıqlı mövzu əsas mövzudur;
> standart seçim `system`-dir. Standart palitra kitin **Editions** görünüşüdür
> (isti kağız neytral rəngləri və mis aksent `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); Parametrlər →
> Görünüş → Rəng palitrası bölməsində laym aksentli, kitin əsas tokenlərindən ibarət **Classic** seçimi mövcuddur. Switzer
> UI, ekran və kod mətnləri üçün yeganə şrift ailəsidir (`--ci-font-ui`; `--ci-font-display` və
> `--ci-font-mono` ona yönəlir) və kitin özü tərəfindən lokal şəkildə təmin edilir (`packages/ui-kit/src/ci-fonts.css`,
> `ci-tokens.css` tərəfindən idxal olunur). Switzer-də olmayan yazı sistemləri qlif-qlif alternativ şriftə keçir (`src/app/globals.css`):
> kiril, yunan və vyetnam yazıları üçün Inter, ərəb yazısı üçün isə yalnız `html[dir="rtl"]` daxilində Vazirmatn istifadə olunur.
> Hər bir ikon Lucide qlifidir.

## 1. Elementlər harada yerləşir

- **Kit.** `packages/ui-kit/src`, `packages/ui-kit/UPSTREAM.md` faylında sabitlənmiş commit-dəki yuxarı axının `src/` kataloqunun bayt-bayt eyni nüsxəsidir (`packages/ui-kit/UPSTREAM.md` həmçinin lisenziya icazəsini qeydə alır); `PATCHES.md` lokal yamaları sadalayır (heç biri yoxdur). O, heç bir yığım olmadan mənbə kimi istifadə edilir: `next.config.mjs` onu transkompilyasiya edir, `tsconfig.json` isə `@omniroute/ui-kit` → `packages/ui-kit/src` və `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` uyğunlaşdırmalarını müəyyən edir (`vitest.config.ts` və `vitest.mcp.config.ts` eyni aliası ehtiva edir). Kit komponentini onun alt yolundan (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) import edin, heç vaxt `@omniroute/ui-kit` ümumi ixrac modulu vasitəsilə deyil: ümumi ixrac modulu hər komponenti (tarix seçicisi də daxil olmaqla) hər import edən modulun daxilinə çəkir. Kitin üslub cədvəli `src/app/globals.css` vasitəsilə daxil olur (`@import "../../packages/ui-kit/src/ci-styles.css"`, tam üslub cədvəli: əsas `ci-ui.css` və bütün naxış ailələri).
- **Tokenlər.** `packages/ui-kit/src/ci-tokens.css`, `--ci-*` tokenlərini elan edir; `src/app/globals.css` onları köhnə OmniRoute adları ilə (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) əlaqələndirir ki, mövcud `var(--color-*)` istifadələri və Tailwind utilitləri işləməyə davam etsin. Yeni kod Tailwind utilitlərindən (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) və ya kit siniflərindən istifadə edir — heç vaxt hex dəyərindən istifadə etmir (`tests/unit/design-kit-bridge.test.ts` bu əlaqələndirməni məcburi edir). `text-primary`, `--text-color-primary` vasitəsilə `--color-primary-ink` dəyərinə çevrilir, buna görə `bg-primary`/`border-primary` vurğu səthini qoruyarkən əsas mətn oxunaqlı qalır: Editions altında bu, kitin `--ci-color-accent-active` dəyəridir (işıqlı rejimdə tünd mis rəngli `#99562f`, qaranlıq rejimdə mis vurğu); Classic altında isə işıqlı rejimdə lime-800, qaranlıq rejimdə laym vurğusudur. Diaqram seriyaları `--color-chart-1` … `--color-chart-8` tokenlərindən istifadə edir; onların hər birində mətn üçün təhlükəsiz `--color-chart-N-ink` və qeyri-şəffaf `--color-chart-N-subtle` nişan çaları var və bunlar kit seriyalarının sırasına (`ciChartSeriesOrder`) uyğun təyin edilir.
- **Temalar.** `<html className="ci-theme">` (`src/app/layout.tsx`) sənədi kit temasına qoşur. Seçim `light`, `dark` və ya `system` ola bilər (`src/shared/constants/appConfig.ts` daxilində `THEME_CONFIG.defaultTheme = "system"`; `system`, `prefers-color-scheme` seçimini izləyir). `src/store/themeStore.ts` daxilindəki `applyTheme()` (hidratasiya başlamazdan əvvəl icra edilən və `src/app/layout.tsx` daxilində sətirdaxili yerləşdirilən `THEME_BOOT_SCRIPT` tərəfindən təkrarlanır) eyni vaxtda `data-theme="dark"|"light"` atributunu təyin edir və `<html>` üzərində `.dark` sinfini dəyişdirir. Kitin qaranlıq tokenlər dəsti `data-theme="dark"` əsasında seçilir (`packages/ui-kit/src/ci-tokens.css`); OmniRoute-un öz qaranlıq rejim əvəzləmələri (`globals.css` daxilindəki `.dark` bloku) və köhnə Tailwind `dark:` utilitləri `.dark` sinfi əsasında işləyir. Vurğu rəngi üçün əvvəlcədən təyin edilmiş variantlar yoxdur: vurğu həmişə kitdən gəlir və daha köhnə yığımdan yadda saxlanmış variant anbar yüklənəndə silinir.
- **Palitralar.** Hər ikisi kitdən gələn iki palitra var (`src/shared/constants/appearancePalette.ts`): standart olan `editions` və `classic`. Editions, `<html>` üzərindəki kitə məxsus `data-ci-appearance="editions"` atributudur və `ci-editions.css` (`ci-ui.css` tərəfindən import edilir) bunu `data-theme` ilə birləşdirir; Classic isə bu atributun olmamasıdır. Kök maket atributu serverdə render edir, buna görə yaddaşda heç nə saxlanmayan (və ya JS-i olmayan) ziyarətçi bütün səthlərdə — idarə panelində, giriş səhifəsində, `/status`, xəta səhifələrində, `/docs` və PWA-da — Editions əldə edir. Seçim tema ilə yanaşı eyni `theme` anbarında saxlanılır (`src/store/themeStore.ts` daxilində `palette`, `setPalette()`, `applyPalette()`) və rəngləmədən əvvəl `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, maketin `<head>` hissəsində sətirdaxili yerləşdirilir) tərəfindən tətbiq olunur; o, atributu yalnız saxlanmış palitra `"classic"` olduqda silir. Kök maketdən kənarda olan `src/app/global-error.tsx` onu eyni anbardan tətbiq edir. `data-ci-appearance` atributunu başqa heç bir elementə əlavə etməyin: kit onu `html:root:has([data-ci-appearance="editions"])` ilə uyğunlaşdırır, buna görə atributa malik bir alt element bütün sənədi dəyişər. Editions üçün `data-ci-editions-variant="landing"` variantı idarə paneli üçün deyil, marketinq səhifələri üçündür. Brauzer interfeysi: server standart Editions rəngini `viewport.themeColor` daxilində (`prefers-color-scheme` başına bir teq) və veb manifestdə render edir — `src/shared/constants/pwaThemeColors.ts` daxilindəki `PWA_THEME_COLORS`, Editions `--ci-color-background` dəyərinin (`#f3f1e9` / `#11120f`) yeganə nüsxəsidir və `tests/unit/pwa-theme-colors.test.ts` vasitəsilə `ci-editions.css` ilə sabitlənir. Daha sonra canlı `<meta name="theme-color">` saxlanmış palitranı və rejimi izləyir: `THEME_BOOT_SCRIPT` teqləri rəngləmədən əvvəl yenidən yazır, tema anbarının əməliyyatları isə bunu hər dəyişiklikdə edir (`src/shared/utils/themeColorMeta.ts` daxilində `resolveThemeColor()` / `applyThemeColor()`; `CLASSIC_PAGE_BACKGROUND` kitin `ciTokens` dəyərindən oxunur). Açıq şəkildə seçilmiş işıqlı/qaranlıq tema hər teqi həmin rejimə təyin edir; `system` isə hər sxem üçün bir rəng saxlayır. Manifest Editions olaraq qalır: o, seçim olmadan hər quraşdırma üçün bir dəfə əldə edilir. Monaco rənglərini yoxlama elementindən oxuyur (`monacoKitTheme.ts`); Editions altında yoxlama oxunuşu bir sinxron keçid üçün kökün `data-theme` dəyərini dəyişir, çünki kit Editions-ın işıqlı/qaranlıq rejimini kök elementə əsasən müəyyən edir.
- **Komponentlər (adapterlər).** `src/shared/components/index.tsx` OmniRoute komponent API-sini (eyni adlar, standart ixraclar və proplar) qoruyur və onun arxasındakı primitivlər kit üzərində qurulmuş adapterlərdir: formalar (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), üst qatlar və əks əlaqə (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), struktur (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) və cədvəllər (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Adapter kit komponentini alt yolu ilə import edir və köhnə propları ona uyğunlaşdırır — məsələn, `Button variant="primary"` kitin `default` düyməsidir (`--ci-button-primary-*`: işıqlı rejimdə tərs səth, qaranlıq rejimdə isə `--ci-color-accent-foreground` mətn rəngi ilə vurğu), `danger` — `destructive`, `warning` isə `outline` və `.ci-button--warning` genişləndirməsidir. `globals.css` faylının sonundakı (`@layer components`) `.ci-button--warning` və `.ci-badge[data-tone]` qaydaları kit sinifləri üzərində qurulmuş OmniRoute genişləndirmələridir. `tests/unit/ui/adapters/*.test.tsx` hər adapteri sabitləyir.
- **Qabıq.** `src/app/(dashboard)/layout.tsx` `DashboardLayout` komponentini render edir; bu komponent
  `src/shared/components/layouts/DashboardShell.tsx` faylını render edir: kitin `SidebarProvider` / `Sidebar` /
  `SidebarInset` komponentləri (`packages/ui-kit/src/sidebar.tsx`) və OmniRoute-un naviqasiya məntiqi
  `src/shared/components/Sidebar.tsx` faylında yerləşir. `#main-content` ünvanına aparan “məzmun bölməsinə keç” linki
  fokuslana bilən ilk elementdir. `src/shared/components/Header.tsx` kitin `SidebarTrigger` komponentini (shell-un
  yeganə sidebar dəyişdiricisi), Keak `ProductSwitcher` komponentini və command-palette açılışını ehtiva edir; kitə
  aid heç bir `PageHeader` (`.ci-page-header`) `#main-content` daxilində quraşdırılmadıqda marşrut başlığını göstərir.
  Buna görə öz `PageHeader` komponenti olan səhifədə yalnız bir `h1` olur. `src/shared/components/CommandPalette.tsx`
  kitin `Dialog` komponentidir.
- **İkonlar.** `<Icon name="material_name">` (`src/shared/components/Icon.tsx`) adı ekranların istifadə etdiyi
  Material Symbols lüğəti vasitəsilə `ICON_MAP` (`src/shared/constants/iconMap.ts`) daxilindəki uyğun Lucide
  qlifinə çevirir. Material Symbols şrifti və paketi artıq yoxdur: xəritədə olmayan ad neytral yer tutucu qlif
  (`data-icon-missing="true"`) render edir və production xaricində konsol xəbərdarlığı qeyd edir.
  `npm run gen:icon-map` xəritədə olmayan və istifadədə olan adları çap edir
  (`tests/unit/icon-map-coverage.test.ts` Lucide ikonası olmayan hər hansı ad üçün uğursuz olur;
  `tests/unit/icon-map-object-values.test.ts` axtarış obyektlərində saxlanılan adları əhatə edir);
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` literal
  `<span className="material-symbols-outlined">` elementlərini `<Icon>` elementlərinə yenidən yazır.
- **Brend.** `src/shared/components/OmniRouteLogo.tsx` kitin komponentlərini əhatə edir: standart export olan
  `OmniRouteLogo` `ProductIcon product="omniroute" variant="glyph"` komponentini (inline SVG, `basePath` ilə
  təhlükəsiz) render edir, `OmniRouteLockup` isə `ProductLockup product="omniroute"` komponentini (əlçatan adı
  “Keak OmniRoute”) və ya white-label operatorlar üçün onların `name`/`logoSrc` dəyərlərini render edir.
  Məhsul dəyişdiricisinin təyinatları `src/shared/constants/keakProducts.ts` daxilində yerləşir
  (`KEAK_PRODUCT_LINKS`, `KEAK_ACTIVE_PRODUCT`). Ayrı ekranlar —
  `src/app/login/page.tsx`, `src/app/status/page.tsx`, `src/app/maintenance/page.tsx`,
  `src/app/offline/page.tsx`, `src/app/not-found.tsx` və `src/shared/components/ErrorPageScaffold.tsx` —
  lockup komponentini göstərir; `tests/unit/brand-pages-static.test.ts` bunu qoruyur.

## 2. Qaydalar

1. Tokenlər, heç vaxt literallar deyil. Məqsədli saxlanılan istisnalar: həmişə tünd konsol terminalı və
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`), literal hex dəyərinə ehtiyacı olan çağırışçılar
   üçün kit status palitrasının həll edilmiş hex əksi. Kateqorik palitralar artıq istisna deyil:
   onlar kitin səkkiz diaqram tokeninə (`--color-chart-1..8`, həmçinin `-ink`/`-subtle`), kit seriyalarının
   sırasına uyğun olaraq, `src/shared/utils/categoricalPalette.ts` və marşrutlaşdırma strategiyaları
   üçün `src/app/(dashboard)/dashboard/combos/strategyPalette.ts` vasitəsilə əsaslanır; ReactFlow
   kənarları və orkestrasiya kətanı temadan asılı `--orch-status-*` dəyişənlərini oxuyur
   (`src/shared/components/flow/edgeStyles.ts`).
2. `packages/ui-kit/src` qovluğuna heç vaxt əl ilə düzəliş etməyin: `scripts/dev/sync-ui-kit.sh <commit>` ilə
   sinxronlaşdırın; pre-commit yoxlaması `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) sabitlənmiş
   upstream commit-dən fərqlənən istənilən bayt olduqda uğursuz olur (upstream klonu,
   `UI_KIT_CLONE` və ya `_references/cheaper-inference-ui-kit` olmadıqda xəbərdarlıqla ötürülür). Kitdə
   nəsə çatışmırsa, adapterdə və ya ekranda alternativ həll tətbiq edin və bunu upstream-dən istəyin.
3. Kit mətnlərinin standart dəyərləri ingiliscədir (`label = "Loading"`, `loadingLabel = "Loading table"`…) —
   kit komponenti mətn göstərdikdə `useTranslations(...)` vasitəsilə tərcümə edilmiş sətirləri ötürün.
4. Tailwind utilitləri kit komponentlərinin siniflərindən üstündür (kit
   `@layer theme, base, components, utilities` elan edir və qaydaları `components` daxilində yerləşir) —
   kit komponentlərinin rəngini dəyişmək üçün deyil, boşluq və yerləşdirmə üçün utilitlərdən istifadə edin.
5. Başlıqlar: səhifə və bölmə başlıqları üçün `.ci-heading`; yalnız xəta səhifəsindəki status kodu kimi böyük,
   seyrək displey mətnləri üçün `.ci-dashboard-display`. Hər ikisi Switzer istifadə edir.
6. `tests/unit/dashboard-kit-sweep.test.ts` kitin tətbiqini qoruyur: `src/app` və ya
   `src/shared/components` altında Material ligature span-ı olmamalıdır; dashboard ağacında (`src/app/(dashboard)`
   və `src/shared/components`) xam `<select>`, `<textarea>` və ya `<table>` olmamalıdır və sadalanan
   istisnalardan (`Select` adapter-inin native branch-i, `RequestLoggerDetail`) kənarda əl ilə hazırlanmış
   `role="dialog"` olmamalıdır; oradakı hər bir xam `<button>` və ya `<input>` üçün ondan ən çoxu 3 sətir
   yuxarıda səbəbi ehtiva edən `kit-exception:` şərhi olmalıdır; palitra çalarları və `dark:` variantları
   yalnız testin sadaladığı fayllarda ola bilər.
7. PR-dan əvvəl hər iki temanı və 390 px görünüş sahəsini yoxlayın (ekran görüntüləri); `tests/e2e/a11y.spec.ts`
   axe-i işə salır.

## 3. Ekran əlavə etmək

1. Səhifəni kit `PageHeader` ilə açın (`@omniroute/ui-kit/page-header`, dashboard daxilində `compact`) —
   başlıq, təsvir və `actions`. Sonra shell başlığı öz başlığını atır.
2. İdarəetmə elementlərini `@/shared/components`-dən (adapterlər) qurun və adapter olmadıqda kit
   komponentlərindən alt-yol ilə istifadə edin (`Table`/`TableScrollArea`/`DataTableShell`, `Field`,
   `Alert`, `Tabs`, `RadioGroup`, `Slider`…).
3. İkonlar: `<Icon name="…" />`. Yeni ad semantik cəhətdən uyğun Lucide komponenti ilə `ICON_MAP`-ə əlavə
   edilir; `npm run gen:icon-map` hələ də çatışmayan adları siyahılayır.
4. Rənglər: semantik utility-lər (`text-success`, `bg-warning-bg`, `border-border`…) və qrafik seriyaları
   üçün `var(--color-chart-N)`; hex dəyərlər və yalnız rəngi təkrarlayan `dark:` variantları yoxdur.
5. Mətn: kit komponentlərinə ötürdüyünüz etiketlər daxil olmaqla hər sətir `useTranslations`-dan gəlir. Yeni
   açarlar `src/i18n/messages/en.json`, `pt-BR.json` və `vi.json`-a əlavə edilir (Vyetnam paritet testi
   hər ingilis açarını sabitləyir); digər lokallar i18n sinxronizasiyası ilə doldurulur.
6. PR-dan əvvəl qoruyucuları işə salın: `tests/unit/dashboard-kit-sweep.test.ts`,
   `tests/unit/icon-map-coverage.test.ts`, `tests/unit/icon-map-object-values.test.ts`,
   `npm run check:dashboard-typecheck` (`iconMap.ts`-də təkrarlanmış import-u tutan yeganə yoxlama),
   `npm run check:ui-icu` və ekranın öz testləri.

## 4. Adapter əlavə etmək və ya dəyişdirmək

1. `src/shared/components/index.tsx` faylının publik API-sini saxlayın: eyni export adları, default export-lar və qəbul edilən prop-lar. Köhnə prop-ları adapter daxilində kit-ə uyğunlaşdırın (bax: `Button.tsx`: `VARIANT_TO_KIT`, `SIZE_TO_KIT`).
2. Kit-i subpath ilə import edin (`@omniroute/ui-kit/<component>`).
3. Kit boşluqları üçün müvəqqəti həllər adapter-də (və ya düzəliş stil olduqda `globals.css` faylında `@layer components` içərisində) yerləşir, heç vaxt `packages/ui-kit/src`-də yox.
4. `tests/unit/ui/adapters/<name>.test.tsx` əlavə edin və ya yeniləyin. Çox sayda çağırıcısı olan adapter üçün dəyişiklikdən əvvəl və sonra render olunmuş markup-u müqayisə edin — padding və ya wrapper dəyişiklikləri bütün ekranlara yayılır.

## 5. Kitin yenilənməsi

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` də bərkidilmiş versiyanı yuxarı repo-nun ən yeni `v*` teqi ilə müqayisə edir və buraxılış bitdikdə sinxronizasiya əmrini çap edir.

Gündəlik `UI Kit upstream watch` iş axını (`.github/workflows/ui-kit-upstream-watch.yml`) eyni yoxlamanı həyata keçirir. Sancaq arxada olarkən, `scripts/ci/ui-kit-sync-pr.sh` `chore/ui-kit-sync-latest` yuvarlanan budaqda ən yüksək `release/vX.Y.Z` budağına qarşı bir sinxronizasiya PR açıq saxlayır. O, heç vaxt birləşmir: hər dəst buraxılışı hələ də yerli VPS üzərində vizual yoxlamaya ehtiyac duyur. Daha yeni buraxılış çıxdıqda filial yenidən qurulur və əks halda tək qalır. Əl ilə itələnən açıq PR üzərinə yazılmır və qoruyucunun bağlandığı, birləşdirilməmiş versiya üçün PR daha yeni buraxılışa qədər bağlı qalır.

Heç bir PR açılmadıqda (hədəf buraxılış dondurulduqda, PR əl ilə itələdi, PR bağlandı və ya heç bir PR nişanı təyin olunmadı) iş axını səbəbini bildirən bir izləmə məsələsini açıq saxlayır.

İş prosesi iki sirrdən istifadə edir:

- `secrets.UI_KIT_READ_TOKEN`: şəxsi yuxarı repo üçün yalnız oxuna bilən işarədir. İş axını yuxarı axını oxuya bilmədikdə (token yoxdur, işləməyi dayandıran işarə və ya GitHub əlçatmazdır) qaçış yaşıl qalır, lakin xəbərdarlıq yazır və bir ayrı məsələni açıq saxlayır, bu da sonrakı qaçış yuxarı axını təkrar oxuya bildikdə özünü bağlayır.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Məzmun və Çəkmə sorğuları yazma girişi olan bu depoda incə dənəli işarədir. Defolt `GITHUB_TOKEN` burada PRs yarada bilməz və onun açdığı PR CI işə salmaz. Bu işarə olmadan iş axını yalnız filialı itələyir.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` həmin öhdəçilikdə yuxarı axın `src/` (`latest` = ən yeni `v*` teq) `packages/ui-kit/src`-ə kopyalayır, tək icazə verilən transformasiyanı tətbiq edir (nisbi idxaldan `.js` şəkilçisini çıxarır) və iş sahəsinin `packages/ui-kit/package.json` və `package-lock.json` versiyasını yuxarı axına təyin edir. Sonra: `git diff packages/ui-kit` nəzərdən keçirin, hər iki mövzuda provayderlər, parametrlər, kombinasiyalar, istifadə və son nöqtə haqqında vizual keçid edin, `npm run check:ui-kit-snapshot` və `npm run test:vitest:ui` işə salın və yuxarı axın dəyişiklik jurnalı ilə PR açın.

## 6. README diaqramları

Kök `README.md` faylının daxil etdiyi on iki diaqram (`docs/diagrams/*.svg`) statik təsvirə tətbiq edilmiş kitdir və onlar əl ilə çəkilmir, generasiya edilir: `scripts/docs/gen-readme-*.mjs` daxilində 13 generator faylı (on iki diaqram və `gen-readme-diagrams.mjs` drayveri) və `tests/unit/docs/readme-*-svg.test.ts` daxilində hər diaqram üçün bir olmaqla 12 köhnəlmə testi var; hər biri repozitoriyaya daxil edilmiş faylı öz generatorunun çıxışı ilə bayt-bayt müqayisə edir (`test-unit` tapşırığı).

- **Tokenlər.** `scripts/docs/readme-diagram-theme.mjs` Editions palitrasını (standart görünüşü) `packages/ui-kit/src/ci-editions.css` faylından köçürür (`tests/unit/docs/readme-diagram-theme.test.ts` vasitəsilə həmin fayla sabitlənib; bu test, həmçinin hər iki sxemdə hər səth üzərində bütün mətn rəngləri üçün WCAG AA uyğunluğunu yoxlayır; yeganə istisna açıq sxemdəki `warn` rəngidir — kitdəki dəyər kətan üzərində 4.46:1 olduğuna görə kit xəbərdarlıq rəngi 10 % tündləşdirilib) və kitin şrift ölçüsü şkalasında (`ci-tokens.css`) mətn rollarını müəyyənləşdirir: hər şey üçün kitin çəkilərində (400/500/600, başlıq üçün 500) və hərf aralığında Switzer; yalnız kod rolları (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`) istisnadır — onlar IBM Plex Mono istifadə edir və yalnız əmrlər, URL-lər, identifikatorlar və terminal ekranları üçündür.
  Açıq sxemin dəyərləri fayl daxilində `:root` üzərində, tünd sxemin dəyərləri isə `prefers-color-scheme: dark` arxasında yerləşir; beləliklə, hər təsvir GitHub-da baxanın sxeminə uyğunlaşır.
- **Şriftlər.** GitHub Markdown heç bir CSS daşımır və camo proksisi bütün xarici sorğuları bloklayır, buna görə də kitin şrifti faylın daxilində daşınmalıdır. Hər generatorun son addımı olan `scripts/docs/readme-outline.mjs`, Switzer rollarını HarfBuzz ilə formalaşdırır və onları vektor konturları (`<defs>` yolları və `<use>`) kimi çəkir; Switzer-də olmayan oxlar və həndəsi simvollar isə onun öz metrikalarına əsasən çəkilir. Yalnız konturlardan istifadə edilir, daxil edilmiş şriftdən heç vaxt istifadə edilmir: Switzer lisenziyası (`packages/ui-kit/src/fonts/FFL.txt`) yazılı razılıq olmadan alt dəst yaratmağı və format çevirməsini qadağan edir, lakin vektor təsvirlərinə icazə verir; buna görə də Switzer `@font-face` və ya `data:` URI-sini yenidən əlavə etməyin. Faylda qalan yeganə şrift real kod mətni kimi saxlanılan hissələr üçün OFL lisenziyalı IBM Plex Mono alt dəstidir (`scripts/docs/readme-fonts.mjs`) və həmin simvollardan yaradılır; daxil edə bilmədiyi istənilən qlif xəta yaradır.
- **Yenidən generasiya.** `npm run docs:readme-diagrams` on iki diaqramın hamısını README sırası ilə yenidən yazır və hər fayl üçün ölçüsü ilə birlikdə bir sətir çap edir. Ayrı-ayrı generatorlar da müstəqil şəkildə işlədilə bilər (`node scripts/docs/gen-readme-<name>.mjs`; `free-tier-budget` üçün `node --import tsx/esm` tələb olunur, çünki onun göstəriciləri `open-sse/config/freeModelCatalog.ts` daxilindəki canlı kataloq yükləyicisindən gəlir; kataloq dəyişikliyinin CI nəticəsi `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` bölməsində göstərilib). Generatoru və SVG-ni birlikdə kommit edin.
- **Yoxlama.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` faylı GitHub-ın təqdim etdiyi şəkildə (`<img>` teqi, camo-nun `Content-Security-Policy` qaydası, `image/svg+xml`) render edir, açıq və tünd rejim kadrlarını çəkir və səhifənin etdiyi xarici şrift sorğularını bildirir (0 olmalıdır).
- **Ölçü limiti.** Hər fayl 200 KB-dan kiçik olmalıdır (hər köhnəlmə testi bunu yoxlayır); 500 KB istənilən README təsviri üçün sərt yuxarı həddir (SVG studio validatorunun qaydası).
- **Mətn dəyişməzdir, rəqəmlər yoxlama mexanizmindən gəlir.** Rebrendinq mətnləri deyil, şrifti və palitranı dəyişdi: hər generator öz diaqramının mətnini həm çəkilən mətn, həm də konturlama addımının girişi olan `*_COPY` sabitində saxlayır (və ya canlı kataloqdan yaradır). Kanonik göstəricilər `<text>` düyünlərində saxlanılır (konturlandıqdan sonra görünməzdir, `fill-opacity:0`) və `check:docs-counts` (`scripts/check/check-docs-counts-sync.mjs`) tərəfindən oxunur; bu yoxlama mexanizminin oxuduğu diaqramların köhnəlmə testləri onun validatorlarını generasiya edilmiş fayl üzərində də işə salır. Buna görə də kodla uyğunsuzlaşan göstərici testin uğursuz olmasına səbəb olur — generator daxilindəki rəqəmi deyil, yoxlama mexanizminin oxuduğu mənbəni düzəldin.
