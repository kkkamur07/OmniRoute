> **સ્થિતિ:** ડૅશબોર્ડ **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) પર બનેલું છે, જેને વર્કસ્પેસ
> `packages/ui-kit` (`@omniroute/ui-kit`; અપસ્ટ્રીમ સ્નૅપશૉટ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલો છે
> અને `npm run check:ui-kit-snapshot` દ્વારા સુરક્ષિત છે) તરીકે વેન્ડર કરવામાં આવ્યું છે. લાઇટ એ પ્રમાણભૂત
> થીમ છે; ડિફૉલ્ટ પસંદગી `system` છે. ડિફૉલ્ટ પૅલેટ કિટનું **એડિશન્સ** સ્વરૂપ છે
> (ઉષ્માભર્યા કાગળ જેવા તટસ્થ રંગો અને કૉપર ઍક્સેન્ટ `#e5ac82`, `packages/ui-kit/src/ci-editions.css`); સેટિંગ્સ →
> દેખાવ → રંગ પૅલેટમાં **ક્લાસિક**, એટલે કે લાઇમ ઍક્સેન્ટ સાથે કિટના બેઝ ટોકન્સનો વિકલ્પ મળે છે. UI,
> ડિસ્પ્લે અને કોડ ટેક્સ્ટ માટે Switzer એકમાત્ર ફૉન્ટ ફૅમિલી છે (`--ci-font-ui`; `--ci-font-display` અને
> `--ci-font-mono` તેનું જ નિરાકરણ કરે છે), જેને કિટ પોતે સેલ્ફ-હોસ્ટ કરે છે (`packages/ui-kit/src/ci-fonts.css`,
> જે `ci-tokens.css` દ્વારા ઇમ્પોર્ટ થાય છે). Switzer માં ન હોય તેવી લિપિઓ માટે ગ્લિફ-દર-ગ્લિફ ફૉલબૅક થાય છે (`src/app/globals.css`):
> સિરિલિક, ગ્રીક અને વિયેતનામી માટે Inter અને માત્ર `html[dir="rtl"]` હેઠળ અરબી લિપિ માટે Vazirmatn વપરાય છે.
> દરેક આઇકન Lucide ગ્લિફ છે.

## 1. વસ્તુઓ ક્યાં રહે છે

- **કિટ.** `packages/ui-kit/src` એ `packages/ui-kit/UPSTREAM.md` માં પિન કરેલા કમિટ પરના અપસ્ટ્રીમ `src/` ની byte-for-byte નકલ છે (જે લાઇસન્સની મંજૂરી પણ નોંધે છે); `PATCHES.md` સ્થાનિક પેચોની યાદી આપે છે (કોઈ નથી). તેનો ઉપયોગ સ્રોત તરીકે થાય છે, કોઈ બિલ્ડ વિના: `next.config.mjs` તેને transpile કરે છે, અને `tsconfig.json` `@omniroute/ui-kit` → `packages/ui-kit/src` તથા `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` મેપ કરે છે (`vitest.config.ts` અને `vitest.mcp.config.ts` માં પણ એ જ alias છે). કિટના કમ્પોનેન્ટને તેના subpath દ્વારા (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…), ક્યારેય `@omniroute/ui-kit` barrel દ્વારા ઇમ્પોર્ટ ન કરો: barrel દરેક importer માં દરેક કમ્પોનેન્ટ (date picker સહિત) ખેંચી લે છે. કિટની stylesheet `src/app/globals.css` મારફતે આવે છે (`@import "../../packages/ui-kit/src/ci-styles.css"`, સંપૂર્ણ sheet: core `ci-ui.css` ઉપરાંત દરેક pattern family).
- **ટોકન્સ.** `packages/ui-kit/src/ci-tokens.css` `--ci-*` ટોકન્સ જાહેર કરે છે; `src/app/globals.css` તેમને જૂના OmniRoute નામો (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) સાથે જોડે છે, જેથી હાલના `var(--color-*)` reads અને Tailwind utilities કાર્યરત રહે. નવો કોડ Tailwind utilities (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) અથવા કિટ classes નો ઉપયોગ કરે છે — ક્યારેય hex value નહીં (`tests/unit/design-kit-bridge.test.ts` આ bridge લાગુ કરે છે). `text-primary` `--text-color-primary` મારફતે `--color-primary-ink` પર resolve થાય છે, તેથી primary text વાંચી શકાય તેવું રહે છે, જ્યારે `bg-primary`/`border-primary` accent surface જાળવી રાખે છે: Editions હેઠળ તે કિટનું `--ci-color-accent-active` છે (light માં ઘેરો copper `#99562f`, dark માં copper accent); Classic હેઠળ light માં lime-800 અને dark માં lime accent. Chart series `--color-chart-1` … `--color-chart-8` નો ઉપયોગ કરે છે, જેમાં દરેક માટે text-safe `--color-chart-N-ink` અને opaque `--color-chart-N-subtle` chip tint છે, જે કિટના series ક્રમ (`ciChartSeriesOrder`) મુજબ ફાળવાય છે.
- **થીમ્સ.** `<html className="ci-theme">` (`src/app/layout.tsx`) દસ્તાવેજને કિટ થીમમાં opt કરે છે. પસંદગી `light`, `dark` અથવા `system` છે (`src/shared/constants/appConfig.ts` માં `THEME_CONFIG.defaultTheme = "system"`); `system`, `prefers-color-scheme` ને અનુસરે છે. `src/store/themeStore.ts` માં `applyTheme()` (`src/app/layout.tsx` માં inline કરેલા `THEME_BOOT_SCRIPT` દ્વારા mirror કરાયેલ, જે hydration પહેલાં ચાલે છે) `data-theme="dark"|"light"` સેટ કરે છે અને `<html>` પર `.dark` class ને એકસાથે toggle કરે છે. કિટનો dark token set `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) પર આધારિત છે; OmniRoute ના પોતાના dark overrides (`globals.css` નો `.dark` block) અને જૂની Tailwind `dark:` utilities `.dark` class પર આધારિત છે. કોઈ accent color presets નથી: accent હંમેશાં કિટમાંથી આવે છે, અને જૂના build માંથી persist થયેલું preset store load થાય ત્યારે દૂર કરવામાં આવે છે.
- **પેલેટ્સ.** બે, બંને કિટમાંથી (`src/shared/constants/appearancePalette.ts`): `editions`, default, અને `classic`. Editions એ `<html>` પર કિટનું `data-ci-appearance="editions"` attribute છે, જેને `ci-editions.css` (`ci-ui.css` દ્વારા import કરાયેલ) `data-theme` સાથે જોડે છે; Classic એ attributeની ગેરહાજરી છે. Root layout આ attribute ને server-render કરે છે, તેથી કશું stored ન ધરાવતા (અથવા JS વિના) visitor ને દરેક surface — dashboard, login, `/status`, error pages, `/docs` અને PWA — પર Editions મળે છે. પસંદગી theme સાથે જ તે જ `theme` store માં persist થાય છે (`palette`, `setPalette()`, `applyPalette()` `src/store/themeStore.ts` માં) અને `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, layout ના `<head>` માં inline કરાયેલ) દ્વારા paint પહેલાં લાગુ થાય છે; stored palette `"classic"` હોય ત્યારે જ તે attribute દૂર કરે છે. `src/app/global-error.tsx`, જે root layout ની બહાર છે, તે જ storeમાંથી તેને લાગુ કરે છે. અન્ય કોઈ element પર `data-ci-appearance` મૂકશો નહીં: કિટ તેને `html:root:has([data-ci-appearance="editions"])` સાથે match કરે છે, તેથી એક descendant આખા દસ્તાવેજને બદલી દેશે. Editions નું `data-ci-editions-variant="landing"` variant marketing pages માટે છે, dashboard માટે નહીં. Browser chrome: server default, Editions, ને `viewport.themeColor` (દરેક `prefers-color-scheme` માટે એક tag) અને web manifest માં render કરે છે — `src/shared/constants/pwaThemeColors.ts` માં `PWA_THEME_COLORS`, જે Editions ના `--ci-color-background` (`#f3f1e9` / `#11120f`) નું એકમાત્ર mirror છે અને `tests/unit/pwa-theme-colors.test.ts` દ્વારા `ci-editions.css` સાથે pinned છે. ત્યારબાદ live `<meta name="theme-color">` stored palette અને mode ને અનુસરે છે: `THEME_BOOT_SCRIPT` paint પહેલાં tags ફરી લખે છે અને theme store ની actions દરેક ફેરફાર વખતે તે કરે છે (`src/shared/utils/themeColorMeta.ts` માં `resolveThemeColor()` / `applyThemeColor()`, જેમાં કિટના `ciTokens` માંથી `CLASSIC_PAGE_BACKGROUND` વાંચવામાં આવે છે). સ્પષ્ટ light/dark theme દરેક tag ને તે mode પર સેટ કરે છે; `system` દરેક scheme માટે એક રંગ જાળવે છે. Manifest Editions જ રહે છે: તે દરેક install દીઠ એકવાર fetch થાય છે, preference વિના. Monaco probe (`monacoKitTheme.ts`) પરથી તેના રંગો વાંચે છે; Editions હેઠળ probe read એક synchronous pass માટે root `data-theme` ને flip કરે છે, કારણ કે કિટ root પરથી Editions light/dark resolve કરે છે.
- **કમ્પોનેન્ટ્સ (adapters).** `src/shared/components/index.tsx` OmniRoute component API (એ જ names, default exports અને props) જાળવે છે, અને તેની પાછળનાં primitives કિટ પરના adapters છે: forms (`Button`, `Input`, `Textarea`, `Checkbox`, `Select`, `Toggle`, `Badge`, `Card`), overlays અને feedback (`Modal`/`ConfirmModal`, `Tooltip`/`InfoTooltip`, `NotificationToast`, `EmptyState`, `Loading`), structure (`Collapsible`, `CollapsibleSection`, `SegmentedControl`, `Breadcrumbs`, `Avatar`) અને tables (`DataTable`, `FilterBar`, `ColumnToggle`, `FilterPills`, `PresetSlider`). Adapter કિટના કમ્પોનેન્ટને subpath દ્વારા import કરે છે અને legacy props ને તેના પર map કરે છે — ઉદાહરણ તરીકે `Button variant="primary"` કિટનું `default` button છે (`--ci-button-primary-*`: light માં inverse surface, dark માં તેના `--ci-color-accent-foreground` ink સાથે accent), `danger`, `destructive` છે, અને `warning`, `.ci-button--warning` extension સાથે `outline` છે. `globals.css` ના અંતે આવેલા `.ci-button--warning` અને `.ci-badge[data-tone]` નિયમો (`@layer components`) કિટ classes પરના OmniRoute extensions છે. `tests/unit/ui/adapters/*.test.tsx` દરેક adapter ને pinned રાખે છે.

## 5. કીટ અપડેટ કરી રહ્યા છીએ

`npm run check:ui-kit-upstream` અપસ્ટ્રીમ રેપોના નવા `v*` ટેગ સાથે `packages/ui-kit/UPSTREAM.md` માં પિન કરેલા સંસ્કરણની તુલના કરે છે અને જ્યારે રીલીઝ બહાર હોય ત્યારે સિંક કમાન્ડ છાપે છે.

દૈનિક `UI Kit upstream watch` વર્કફ્લો (`.github/workflows/ui-kit-upstream-watch.yml`) એ જ ચેક ચલાવે છે. જ્યારે પિન પાછળ હોય છે, ત્યારે `scripts/ci/ui-kit-sync-pr.sh` એક સિંક PR સૌથી વધુ `release/vX.Y.Z` શાખા સામે, રોલિંગ બ્રાન્ચ `chore/ui-kit-sync-latest` પર ખુલ્લું રાખે છે. તે ક્યારેય મર્જ થતું નથી: દરેક કિટ રિલીઝને હજુ પણ સ્થાનિક VPS પર વિઝ્યુઅલ ચેકની જરૂર છે. જ્યારે નવી રીલીઝ બહાર આવે અને અન્યથા એકલી છોડી દેવામાં આવે ત્યારે શાખાનું પુનઃનિર્માણ કરવામાં આવે છે. હાથ વડે દબાણ કરાયેલ કમિટ સાથેનો ઓપન PR ઓવરરાઈટ થતો નથી, અને એવા વર્ઝન માટે PR કે જે જાળવણીકારે બંધ કરેલ અનમર્જ કરેલ હોય તે નવી રિલીઝ સુધી બંધ રહે છે.

જ્યારે કોઈ PR ખોલી શકાતું નથી (લક્ષ્ય પ્રકાશન સ્થિર છે, PR એ હાથથી દબાણ કર્યું છે, PR બંધ હતું, અથવા કોઈ PR ટોકન સેટ નથી) વર્કફ્લો એક ટ્રેકિંગ સમસ્યાને ખુલ્લી રાખે છે જે કહે છે કે શા માટે.

વર્કફ્લો બે રહસ્યોનો ઉપયોગ કરે છે:

- `secrets.UI_KIT_READ_TOKEN`: ખાનગી અપસ્ટ્રીમ રેપો માટે માત્ર વાંચવા માટેનું ટોકન. જ્યારે વર્કફ્લો અપસ્ટ્રીમ વાંચી શકતું નથી (કોઈ ટોકન, ટોકન કે જે કામ કરવાનું બંધ કરે છે, અથવા GitHub અગમ્ય) રન લીલો રહે છે પરંતુ ચેતવણી લખે છે અને એક અલગ મુદ્દો ખુલ્લો રાખે છે, જે પછીથી ચાલ્યા પછી ફરીથી અપસ્ટ્રીમ વાંચી શકે છે તે બંધ થઈ જાય છે.
- `secrets.UI_KIT_SYNC_PR_TOKEN`: સમાવિષ્ટો અને પુલ વિનંતીઓ લખવાની ઍક્સેસ સાથે આ ભંડાર પર એક સરસ ટોકન. ડિફૉલ્ટ `GITHUB_TOKEN` અહીં PRs બનાવી શકતું નથી, અને PR તે ખોલે છે CI ટ્રિગર કરશે નહીં. આ ટોકન વિના વર્કફ્લો માત્ર શાખાને દબાણ કરે છે.

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` તે કમિટ પર અપસ્ટ્રીમ `src/` નકલ કરે છે (`latest` = સૌથી નવું `v*` ટેગ) `packages/ui-kit/src` માં, સિંગલ મંજૂર ટ્રાન્સફોર્મેશન લાગુ કરે છે (તે સંબંધિત આયાતમાંથી `.js` પ્રત્યયને ડ્રોપ કરે છે), અને વર્કસ્પેસ વર્ઝનને `packages/ui-kit/package.json` અને `package-lock.json` માં અપસ્ટ્રીમમાં સેટ કરે છે. પછી: `git diff packages/ui-kit` ની સમીક્ષા કરો, બંને થીમમાં પ્રદાતાઓ, સેટિંગ્સ, કોમ્બોઝ, ઉપયોગ અને એન્ડપોઇન્ટ પર વિઝ્યુઅલ પાસ કરો, `npm run check:ui-kit-snapshot` અને `npm run test:vitest:ui` ચલાવો, અને અપસ્ટ્રીમ ચેન્જલોગ સાથે PR ખોલો.

## 6. README આકૃતિઓ

રૂટ `README.md` માં એમ્બેડ કરેલી બાર આકૃતિઓ (`docs/diagrams/*.svg`) સ્થિર છબી પર લાગુ કરેલી કિટ છે, અને તે હાથથી દોરેલી નહીં પરંતુ જનરેટ કરેલી છે: `scripts/docs/gen-readme-*.mjs` ખાતે 13 જનરેટર ફાઇલો
(બાર આકૃતિઓ ઉપરાંત `gen-readme-diagrams.mjs` ડ્રાઇવર) અને
`tests/unit/docs/readme-*-svg.test.ts` ખાતે 12 જૂનાપણાની કસોટીઓ છે, દરેક આકૃતિ દીઠ એક, જે દરેક કમિટ કરેલી ફાઇલની તેના
જનરેટરના આઉટપુટ સાથે બાઇટ-દર-બાઇટ સરખામણી કરે છે (જોબ `test-unit`).

- **ટોકન્સ.** `scripts/docs/readme-diagram-theme.mjs`, Editions પેલેટ (ડિફૉલ્ટ દેખાવ)ને
  `packages/ui-kit/src/ci-editions.css` માંથી કૉપિ કરે છે (તે ફાઇલ સાથે
  `tests/unit/docs/readme-diagram-theme.test.ts` દ્વારા પિન કરેલું છે, જે બંને સ્કીમમાં દરેક સપાટી પરના દરેક
  ટેક્સ્ટ રંગ માટે WCAG AA પણ ચકાસે છે; એકમાત્ર અપવાદ, લાઇટ `warn`, કિટની ચેતવણીને 10 % ઘેરી કરેલું સ્વરૂપ છે, કારણ કે કિટનું
  મૂલ્ય કૅનવાસ પર 4.46:1 છે) અને કિટના ટાઇપ સ્કેલ (`ci-tokens.css`) પર ટેક્સ્ટ ભૂમિકાઓ વ્યાખ્યાયિત કરે છે: કિટના વેઇટ્સ (400/500/600, ડિસ્પ્લે માટે 500) અને
  દરેક વસ્તુ માટે ટ્રૅકિંગ સાથે Switzer, સિવાય કે કોડ ભૂમિકાઓ (`.cmd`, `.term`, `.term-lg`, `.mono`, `.mono-sm`, `.mono-xs`), જે
  IBM Plex Mono છે અને ફક્ત કમાન્ડ્સ, URLs, આઇડેન્ટિફાયર્સ અને ટર્મિનલ સ્ક્રીનો માટે છે.
  લાઇટ મૂલ્યો ફાઇલની અંદર `:root` પર અને ડાર્ક મૂલ્યો `prefers-color-scheme: dark` પાછળ રહે છે, જેથી દરેક
  છબી GitHub પર દર્શકની સ્કીમને અનુસરે.
- **ફૉન્ટ્સ.** GitHub Markdown કોઈ CSS ધરાવતું નથી અને camo પ્રૉક્સી દરેક બાહ્ય ફેચને અવરોધે છે, તેથી કિટનો ટાઇપ
  ફાઇલની અંદર જ લઈ જવો પડે છે. દરેક જનરેટરના છેલ્લા પગલા તરીકે `scripts/docs/readme-outline.mjs`,
  Switzer ભૂમિકાઓને HarfBuzz વડે શેપ કરે છે અને તેમને વેક્ટર આઉટલાઇન્સ (`<defs>` પાથ્સ અને `<use>`) તરીકે દોરે છે, જ્યારે Switzer માં ન હોય તેવા તીરો
  અને ભૌમિતિક ચિહ્નોને તેના પોતાના મેટ્રિક્સ પર દોરે છે. હંમેશાં આઉટલાઇન્સ, ક્યારેય એમ્બેડ કરેલો ફૉન્ટ નહીં: Switzer નું
  લાઇસન્સ (`packages/ui-kit/src/fonts/FFL.txt`) લેખિત
  સંમતિ વિના સબસેટિંગ અને ફૉર્મેટ રૂપાંતરણને પ્રતિબંધિત કરે છે અને વેક્ટર ડ્રૉઇંગ્સને મંજૂરી આપે છે, તેથી Switzer `@font-face` અથવા `data:` URI ફરીથી ઉમેરશો નહીં. ફાઇલમાં
  બાકી રહેલો એકમાત્ર ફૉન્ટ વાસ્તવિક કોડ ટેક્સ્ટ તરીકે રહેતી સામગ્રી માટેનો OFL IBM Plex Mono સબસેટ
  (`scripts/docs/readme-fonts.mjs`) છે, જે તે અક્ષરોમાંથી બનાવેલો છે; તે એમ્બેડ ન કરી શકે એવો કોઈપણ ગ્લિફ ભૂલ સર્જે છે.
- **ફરીથી જનરેટ કરો.** `npm run docs:readme-diagrams` README ના ક્રમમાં તમામ બારને ફરીથી લખે છે અને દરેક
  ફાઇલ માટે તેના કદ સાથે એક લાઇન પ્રિન્ટ કરે છે. એક જનરેટર સ્વતંત્ર રીતે પણ ચાલે છે (`node scripts/docs/gen-readme-<name>.mjs`;
  `free-tier-budget` ને `node --import tsx/esm` ની જરૂર પડે છે, કારણ કે તેના આંકડા
  `open-sse/config/freeModelCatalog.ts` માંના લાઇવ કૅટલૉગ લોડરમાંથી આવે છે; કૅટલૉગમાં ફેરફારનું CI પરિણામ
  `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict` માં છે). જનરેટર અને SVG ને સાથે કમિટ કરો.
- **પુરાવો.** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` ફાઇલને GitHub જે રીતે સર્વ કરે છે
  તે રીતે રેન્ડર કરે છે (એક `<img>` ટૅગ, camo ની `Content-Security-Policy`, `image/svg+xml`), લાઇટ અને ડાર્ક ફ્રેમ
  કૅપ્ચર કરે છે અને પેજે કરેલી બાહ્ય ફૉન્ટ વિનંતીઓની જાણ કરે છે (0 હોવી આવશ્યક છે).
- **બજેટ.** દરેક ફાઇલ 200 KB કરતાં ઓછી (દરેક જૂનાપણાની કસોટી આની ખાતરી કરે છે); કોઈપણ README
  છબી માટે 500 KB ની સખત મર્યાદા છે (SVG સ્ટુડિયો વૅલિડેટરનો નિયમ).
- **કૉપી યથાવત્, ગણતરીઓ ગેટમાંથી.** રીબ્રાન્ડે ટાઇપ અને પેલેટ બદલ્યાં છે, શબ્દો નહીં: દરેક જનરેટર
  પોતાની આકૃતિની કૉપીને `*_COPY` કૉન્સ્ટન્ટમાં રાખે છે (અથવા તેને લાઇવ કૅટલૉગમાંથી બનાવે છે), જે દોરાયેલું
  ટેક્સ્ટ અને આઉટલાઇનિંગ પગલાનું ઇનપુટ બંને છે. પ્રમાણભૂત આંકડા `<text>` નોડ્સમાં રહે છે (આઉટલાઇન કર્યા પછી અદૃશ્ય,
  `fill-opacity:0`), જેને `check:docs-counts`
  (`scripts/check/check-docs-counts-sync.mjs`) વાંચે છે; ગેટ વાંચે છે તે આકૃતિઓની જૂનાપણાની કસોટીઓ જનરેટ કરેલી
  ફાઇલ પર તેના વૅલિડેટર્સ પણ ચલાવે છે, તેથી કોડથી જુદો પડતો આંકડો કસોટીને નિષ્ફળ બનાવે છે — ગેટ વાંચે છે તે
  સ્રોતને સુધારો, જનરેટરમાંની સંખ્યાને ક્યારેય નહીં.
