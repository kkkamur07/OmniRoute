## 1. အရာများ တည်ရှိရာနေရာ

- **ကစ်။** `packages/ui-kit/src` သည် `packages/ui-kit/UPSTREAM.md` တွင် သတ်မှတ်ထားသော commit ရှိ upstream `src/` ၏ byte-for-byte မိတ္တူဖြစ်သည် (ထိုဖိုင်တွင် လိုင်စင်ခွင့်ပြုချက်ကိုလည်း မှတ်တမ်းတင်ထားသည်)။ `PATCHES.md` တွင် local patch များကို စာရင်းပြုထားသည် (မရှိပါ)။ ၎င်းကို build မလုပ်ဘဲ source အဖြစ် အသုံးပြုသည်။ `next.config.mjs` က ၎င်းကို transpile လုပ်ပေးပြီး `tsconfig.json` က `@omniroute/ui-kit` → `packages/ui-kit/src` နှင့် `@omniroute/ui-kit/*` → `packages/ui-kit/src/*` ဟု mapping လုပ်ပေးသည် (`vitest.config.ts` နှင့် `vitest.mcp.config.ts` တွင်လည်း အလားတူ alias ရှိသည်)။ ကစ် component ကို ၎င်း၏ subpath (`@omniroute/ui-kit/table`, `@omniroute/ui-kit/page-header`…) မှတစ်ဆင့်သာ import လုပ်ပါ။ `@omniroute/ui-kit` barrel မှတစ်ဆင့် မလုပ်ပါနှင့်။ အကြောင်းမှာ barrel သည် importer တစ်ခုချင်းစီထဲသို့ component အားလုံး (date picker အပါအဝင်) ကို ထည့်သွင်းပေးသောကြောင့် ဖြစ်သည်။ ကစ် stylesheet သည် `src/app/globals.css` (`@import "../../packages/ui-kit/src/ci-styles.css"`) မှတစ်ဆင့် ဝင်ရောက်သည်။ ၎င်းသည် အပြည့်အစုံသော stylesheet ဖြစ်ပြီး core `ci-ui.css` နှင့် pattern family အားလုံး ပါဝင်သည်။
- **Tokens။** `packages/ui-kit/src/ci-tokens.css` သည် `--ci-*` token များကို ကြေညာသည်။ `src/app/globals.css` သည် ၎င်းတို့ကို legacy OmniRoute အမည်များ (`--color-*`, `--radius-*`, `--font-sans`/`--font-mono`, `--table-*`, `--orch-status-*`, `--color-fd-*`) နှင့် ချိတ်ဆက်ပေးသောကြောင့် ရှိပြီးသား `var(--color-*)` ဖတ်ရှုမှုများနှင့် Tailwind utility များ ဆက်လက်အလုပ်လုပ်နိုင်သည်။ Code အသစ်တွင် Tailwind utility များ (`bg-surface`, `text-text-muted`, `border-border`, `text-success`, `bg-success-bg`, `bg-chart-1`…) သို့မဟုတ် ကစ် class များကို အသုံးပြုပါ — hex value ကို မည်သည့်အခါမျှ မသုံးပါနှင့် (`tests/unit/design-kit-bridge.test.ts` က bridge ကို စစ်ဆေးအတည်ပြုသည်)။ `text-primary` သည် `--text-color-primary` မှတစ်ဆင့် `--color-primary-ink` သို့ resolve လုပ်သောကြောင့် primary text သည် ဖတ်ရှုရလွယ်ကူနေမည်ဖြစ်ပြီး `bg-primary`/`border-primary` သည် accent surface ကို ဆက်လက်ထိန်းသိမ်းထားသည်။ Editions အောက်တွင် ၎င်းသည် ကစ်၏ `--ci-color-accent-active` (အလင်း mode တွင် နက်ရှိုင်းသော copper `#99562f`၊ အမှောင် mode တွင် copper accent) ဖြစ်ပြီး Classic အောက်တွင် အလင်း mode ၌ lime-800၊ အမှောင် mode ၌ lime accent ဖြစ်သည်။ Chart series များသည် `--color-chart-1` … `--color-chart-8` ကို အသုံးပြုသည်။ တစ်ခုချင်းစီတွင် စာသားအတွက် လုံခြုံသော `--color-chart-N-ink` နှင့် opaque `--color-chart-N-subtle` chip tint ရှိပြီး ကစ်၏ series အစဉ် (`ciChartSeriesOrder`) အတိုင်း သတ်မှတ်ထားသည်။
- **Themes။** `<html className="ci-theme">` (`src/app/layout.tsx`) သည် document ကို ကစ် theme ထဲသို့ ထည့်သွင်းပေးသည်။ preference သည် `light`၊ `dark` သို့မဟုတ် `system` ဖြစ်သည် (`src/shared/constants/appConfig.ts` ရှိ `THEME_CONFIG.defaultTheme = "system"`; `system` သည် `prefers-color-scheme` ကို လိုက်နာသည်)။ `src/store/themeStore.ts` ရှိ `applyTheme()` (hydration မတိုင်မီ လုပ်ဆောင်သည့် `src/app/layout.tsx` ထဲ inline ထည့်ထားသော `THEME_BOOT_SCRIPT` ကလည်း ထပ်တူလုပ်ဆောင်သည်) သည် `data-theme="dark"|"light"` ကို သတ်မှတ်ပြီး `<html>` ပေါ်ရှိ `.dark` class ကို တစ်ပြိုင်နက် toggle လုပ်သည်။ ကစ်၏ dark token set သည် `data-theme="dark"` (`packages/ui-kit/src/ci-tokens.css`) ကို အခြေခံထားသည်။ OmniRoute ၏ ကိုယ်ပိုင် dark override များ (`globals.css` ရှိ `.dark` block) နှင့် legacy Tailwind `dark:` utility များသည် `.dark` class ကို အခြေခံထားသည်။ accent color preset များ မရှိပါ။ accent သည် ကစ်ထံမှသာ အမြဲရရှိပြီး ယခင် build မှ သိမ်းဆည်းထားသော preset ကို store load လုပ်သောအခါ ဖယ်ရှားသည်။
- **Palettes။** နှစ်မျိုးရှိပြီး နှစ်မျိုးလုံးသည် ကစ်မှ ရရှိသည် (`src/shared/constants/appearancePalette.ts`)။ default ဖြစ်သော `editions` နှင့် `classic` တို့ဖြစ်သည်။ Editions သည် `<html>` ပေါ်ရှိ ကစ်၏ `data-ci-appearance="editions"` attribute ဖြစ်ပြီး `ci-ui.css` မှ import လုပ်ထားသော `ci-editions.css` က ၎င်းကို `data-theme` နှင့် ပေါင်းစပ်အသုံးပြုသည်။ Classic သည် ထို attribute မရှိခြင်းဖြစ်သည်။ root layout သည် attribute ကို server-render လုပ်သောကြောင့် သိမ်းဆည်းထားသည့် preference မရှိသော (သို့မဟုတ် JS မရှိသော) visitor သည် dashboard၊ login၊ `/status`၊ error page များ၊ `/docs` နှင့် PWA မျက်နှာပြင်အားလုံးတွင် Editions ကို ရရှိမည်ဖြစ်သည်။ ရွေးချယ်မှုကို theme နှင့်အတူ တူညီသော `theme` store ထဲတွင် သိမ်းဆည်းထားပြီး (`palette`, `setPalette()`, `applyPalette()` in `src/store/themeStore.ts`) `THEME_BOOT_SCRIPT` (`src/shared/utils/themeBootScript.ts`, layout ၏ `<head>` ထဲတွင် inline ထည့်ထားသည်) က paint မလုပ်မီ အသုံးချသည်။ သိမ်းဆည်းထားသော palette သည် `"classic"` ဖြစ်သည့်အခါမှသာ attribute ကို ဖယ်ရှားသည်။ root layout ၏အပြင်ဘက်ရှိ `src/app/global-error.tsx` သည်လည်း တူညီသော store မှ ၎င်းကို အသုံးချသည်။ `data-ci-appearance` ကို အခြား element များတွင် မထည့်ပါနှင့်။ ကစ်သည် ၎င်းကို `html:root:has([data-ci-appearance="editions"])` ဖြင့် match လုပ်သောကြောင့် descendant တစ်ခုတည်းက document တစ်ခုလုံးကို ပြောင်းလဲစေနိုင်သည်။ Editions `data-ci-editions-variant="landing"` variant သည် marketing page များအတွက်ဖြစ်ပြီး dashboard အတွက် မဟုတ်ပါ။ Browser chrome အတွက် server သည် default ဖြစ်သော Editions ကို `viewport.themeColor` ( `prefers-color-scheme` တစ်ခုစီအတွက် tag တစ်ခု) နှင့် web manifest ထဲတွင် render လုပ်သည် — `src/shared/constants/pwaThemeColors.ts` ရှိ `PWA_THEME_COLORS` သည် Editions `--ci-color-background` (`#f3f1e9` / `#11120f`) ၏ တစ်ခုတည်းသော mirror ဖြစ်ပြီး `tests/unit/pwa-theme-colors.test.ts` က ၎င်းကို `ci-editions.css` တွင် သတ်မှတ်ထားကြောင်း အတည်ပြုသည်။ ထို့နောက် live `<meta name="theme-color">` သည် သိမ်းဆည်းထားသော palette နှင့် mode ကို လိုက်နာသည်။ `THEME_BOOT_SCRIPT` သည် paint မလုပ်မီ tag များကို ပြန်ရေးပြီး theme store ၏ action များက ပြောင်းလဲမှုတိုင်းတွင် ထိုသို့လုပ်ဆောင်သည် 3. kit ၏ လစ်လပ်ချက်များအတွက် workaround များကို adapter အတွင်းတွင် (သို့မဟုတ် ပြင်ဆင်ချက်က style ဖြစ်လျှင် `globals.css` `@layer components` အတွင်းတွင်) ထားရှိပါ၊ `packages/ui-kit/src` အတွင်းတွင် လုံးဝ မဟုတ်ပါ။
4. `tests/unit/ui/adapters/<name>.test.tsx` ကို ထည့်ပါ သို့မဟုတ် update လုပ်ပါ။ caller များ များစွာရှိသော adapter တစ်ခုအတွက် ပြောင်းလဲမှုမပြုလုပ်မီနှင့် ပြုလုပ်ပြီးနောက် render လုပ်ထားသော markup ကို နှိုင်းယှဉ်ပါ — padding သို့မဟုတ် wrapper ပြောင်းလဲမှုများသည် screen တိုင်းသို့ ပျံ့နှံ့သွားသည်။

## 5. ပစ္စည်းအစုံကို အပ်ဒိတ်လုပ်ခြင်း။

`npm run check:ui-kit-upstream` `packages/ui-kit/UPSTREAM.md` တွင်ထိုးထားသောဗားရှင်းကို upstream repo ၏နောက်ဆုံးထွက် `v*` tag နှင့် နှိုင်းယှဉ်ပြီး ထွက်ရှိလာသောအခါတွင် ထပ်တူကျသည့်အမိန့်ကို ပရင့်ထုတ်သည်။

နေ့စဉ် `UI Kit upstream watch` အလုပ်အသွားအလာ (`.github/workflows/ui-kit-upstream-watch.yml`) သည် တူညီသောစစ်ဆေးမှုကို လုပ်ဆောင်သည်။ ပင်နံပါတ်နောက်တွင်၊ `scripts/ci/ui-kit-sync-pr.sh` အမြင့်ဆုံး `release/vX.Y.Z` အကိုင်းအခက်နှင့် အဖွင့်တစ်ပြိုင်တည်းဖြစ်သော PR တစ်ခုကို လှိမ့်လိုက်သောကိုင်းဆက် `chore/ui-kit-sync-latest` တွင် ထားရှိထားသည်။ ၎င်းသည် ဘယ်တော့မှ ပေါင်းစပ်မည်မဟုတ်ပါ- အစုံလိုက်ထုတ်လွှတ်မှုတိုင်းသည် local VPS တွင် အမြင်အာရုံစစ်ဆေးမှု လိုအပ်နေသေးသည်။ အသစ်ထွက်ပြီး အခြားနည်းဖြင့် အထီးကျန်နေချိန်တွင် ဌာနခွဲကို ပြန်လည်တည်ဆောက်ပါသည်။ လက်ဖြင့်တွန်းထားသော ကတိကဝတ်များပါသော အဖွင့် PR ထပ်မရေးဘဲ၊ ပြုပြင်ထိန်းသိမ်းသူမှ ပိတ်ထားသော ပေါင်းစပ်မထားသော ဗားရှင်းအတွက် PR အသစ်ထွက်သည့်အချိန်အထိ ပိတ်ထားသည်။

PR ကိုဖွင့်၍မရသောအခါ (ပစ်မှတ်ထုတ်လွှတ်မှုကို အေးခဲသွားသည်၊ PR လက်ဖြင့်တွန်းထုတ်သည်၊ PR ပိတ်ထားသည်၊ သို့မဟုတ် PR တိုကင်ကိုမသတ်မှတ်ထားပါ) အလုပ်အသွားအလာသည် အဘယ်ကြောင့်ဆိုသော် ခြေရာခံခြင်းပြဿနာကို ဖွင့်ထားစေသည်။

အလုပ်အသွားအလာတွင် လျှို့ဝှက်ချက်နှစ်ခုကို အသုံးပြုသည်-

- `secrets.UI_KIT_READ_TOKEN`: သီးသန့် upstream repo အတွက် ဖတ်ရန်-သီးသန့် တိုကင်။ အလုပ်အသွားအလာကို အထက်စီးကြောင်းကို မဖတ်နိုင်သောအခါ (တိုကင်မရှိ၊ အလုပ်မလုပ်တော့သည့် သို့မဟုတ် GitHub မရနိုင်ပါ) run သည် အစိမ်းရောင်ရှိနေသော်လည်း သတိပေးချက်တစ်ခုရေးသားပြီး သီးခြားပြဿနာတစ်ခုကို ဖွင့်ထားကာ ၎င်းသည် နောက်မှပြေးပြီးသည်နှင့် ၎င်းကိုယ်တိုင်ပိတ်သွားပါက အထက်သို့ပြန်ဖတ်နိုင်သည်။
- `secrets.UI_KIT_SYNC_PR_TOKEN`: Contents and Pull Requests ဖြင့် ဝင်ရောက်ရေးသားခွင့် တောင်းဆိုချက်များပါရှိသော ဤသိုလှောင်ခန်းရှိ အနုစိတ်သော တိုကင်တစ်ခု။ မူရင်း `GITHUB_TOKEN` ဤနေရာတွင် PRs ဖန်တီး၍မရပါ၊ ၎င်းကိုဖွင့်ထားသော PR CI အစပျိုးမည်မဟုတ်ပါ။ ဤသင်္ကေတမပါဘဲ အလုပ်အသွားအလာသည် ဌာနခွဲကိုသာ တွန်းပို့သည်။

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]` `src/` commit တွင် (`latest` = the newest `v*` tag) ကို `packages/ui-kit/src` သို့ ကူးယူသည်၊ ခွင့်ပြုထားသော အသွင်ပြောင်းမှုကို အသုံးပြုသည် (၎င်းသည် `.js` ၏ နောက်ဆက်တွဲကို ဆက်စပ်တင်သွင်းမှုများမှ ရုပ်သိမ်းသွားသည်) နှင့် `packages/ui-kit/package.json` နှင့် `package-lock.json` တွင် workspace ဗားရှင်းကို upstream တစ်ခုသို့ သတ်မှတ်သည်။ ထို့နောက်- `git diff packages/ui-kit` ပြန်လည်သုံးသပ်ပါ၊ ပံ့ပိုးပေးသူများ၊ ဆက်တင်များ၊ ပေါင်းစပ်မှုများ၊ အသုံးပြုမှုနှင့် အဆုံးမှတ်ကို အပြင်အဆင်နှစ်ခုလုံးတွင် ပြုလုပ်ပါ၊ `npm run check:ui-kit-snapshot` နှင့် `npm run test:vitest:ui` ကိုဖွင့်ပါ၊ နှင့် PR ကို upstream changelog ဖြင့်ဖွင့်ပါ။

- **စာသားကို မပြောင်းလဲပါနှင့်၊ အရေအတွက်များကို gate မှ ရယူပါ။** Rebrand သည် type နှင့် palette ကိုသာ ပြောင်းလဲခဲ့ပြီး စာလုံးများကို မပြောင်းလဲခဲ့ပါ။ Generator တစ်ခုစီတွင်
  ၎င်း၏ဒိုင်ယာဂရမ်စာသားကို `*_COPY` constant တစ်ခုအဖြစ် ထည့်သွင်းထားသည် (သို့မဟုတ် လက်ရှိ catalog မှ တည်ဆောက်သည်)။ ၎င်းသည်
  ရေးဆွဲထားသော စာသားလည်းဖြစ်သလို outlining အဆင့်၏ input လည်းဖြစ်သည်။ Canonical ကိန်းဂဏန်းများကို `<text>` node များတွင် ဆက်လက်ထားရှိသည် (outline ပြောင်းပြီးနောက်
  `fill-opacity:0` ဖြင့် မမြင်ရတော့ပါ)၊ ၎င်းတို့ကို `check:docs-counts`
  (`scripts/check/check-docs-counts-sync.mjs`) က ဖတ်သည်။ ထို gate က ဖတ်ရှုသော ဒိုင်ယာဂရမ်များ၏ staleness test များသည်လည်း
  generate လုပ်ထားသောဖိုင်ပေါ်တွင် ၎င်း၏ validator များကို run သဖြင့် ကိန်းဂဏန်းတစ်ခုက code နှင့် ကွဲလွဲသွားပါက test မအောင်မြင်ပါ — generator ထဲရှိ
  နံပါတ်ကို မပြင်ဘဲ gate က ဖတ်သည့် source ကိုသာ ပြင်ပါ။
