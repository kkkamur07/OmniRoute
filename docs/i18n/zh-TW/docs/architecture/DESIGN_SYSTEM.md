> **狀態：**儀表板建構於 **Keak CI UI Kit** (`@keak/cheaper-inference-ui-kit`) 之上，並以工作區
> `packages/ui-kit` (`@omniroute/ui-kit`) 的形式納入版本控制（上游快照固定於
> `packages/ui-kit/UPSTREAM.md`，並由 `npm run check:ui-kit-snapshot` 檢查）。淺色是標準
> 主題；預設偏好設定為 `system`。預設調色盤採用套件的 **Editions** 外觀
> （暖色紙張中性色與銅色強調色 `#e5ac82`，`packages/ui-kit/src/ci-editions.css`）；設定 →
> 外觀 → 調色盤提供**經典**選項，使用套件的基礎權杖與萊姆色強調色。Switzer 是
> UI、展示與程式碼文字共用的唯一字型家族（`--ci-font-ui`；`--ci-font-display` 與
> `--ci-font-mono` 均解析為此字型），並由套件本身自行託管（`packages/ui-kit/src/ci-fonts.css`，
> 由 `ci-tokens.css` 匯入）。Switzer 缺少的文字系統會逐字形回退（`src/app/globals.css`）：
> 西里爾字母、希臘字母與越南文使用 Inter，而阿拉伯文字僅在 `html[dir="rtl"]` 下使用 Vazirmatn。
> 每個圖示皆為 Lucide 字形。

## 1. 各項內容的位置

- **套件。** `packages/ui-kit/src` 是上游 `src/` 在
  `packages/ui-kit/UPSTREAM.md` 所釘選之 commit 的逐位元組複本（該檔案也記錄了授權許可）；`PATCHES.md` 列出本機修補程式（無）。它以原始碼形式使用，不進行建置：`next.config.mjs` 會轉譯它，而 `tsconfig.json` 將 `@omniroute/ui-kit` → `packages/ui-kit/src` 以及 `@omniroute/ui-kit/*` → `packages/ui-kit/src/*`（`vitest.config.ts` 和 `vitest.mcp.config.ts` 也具有相同別名）。請透過子路徑匯入套件元件（`@omniroute/ui-kit/table`、`@omniroute/ui-kit/page-header`…），絕不要透過 `@omniroute/ui-kit` barrel 匯入：barrel 會將所有元件（包括日期選擇器）拉入每個匯入者。套件樣式表透過 `src/app/globals.css` 載入（`@import "../../packages/ui-kit/src/ci-styles.css"`，完整樣式表：核心 `ci-ui.css` 加上每個模式系列）。
- **Token。** `packages/ui-kit/src/ci-tokens.css` 宣告 `--ci-*` token；`src/app/globals.css`
  將它們橋接至舊版 OmniRoute 名稱（`--color-*`、`--radius-*`、`--font-sans`/`--font-mono`、
  `--table-*`、`--orch-status-*`、`--color-fd-*`），因此現有的 `var(--color-*)` 讀取方式和 Tailwind
  utilities 仍可運作。新程式碼使用 Tailwind utilities（`bg-surface`、`text-text-muted`、
  `border-border`、`text-success`、`bg-success-bg`、`bg-chart-1`…）或套件類別 — 絕不使用十六進位值
  （`tests/unit/design-kit-bridge.test.ts` 會強制檢查此橋接）。`text-primary` 會透過 `--text-color-primary` 解析為 `--color-primary-ink`，因此主要文字能保持可讀性，而 `bg-primary`/`border-primary` 維持強調色表面：在 Editions 下，它是套件的
  `--ci-color-accent-active`（淺色模式中的深銅色 `#99562f`，深色模式中的銅色強調色）；在 Classic 下，
  淺色模式為 lime-800，深色模式為 lime 強調色。圖表系列使用
  `--color-chart-1` … `--color-chart-8`，每個都有適合文字使用的 `--color-chart-N-ink` 以及不透明的
  `--color-chart-N-subtle` 色塊色調，並依套件系列順序（`ciChartSeriesOrder`）分配。
- **主題。** `<html className="ci-theme">`（`src/app/layout.tsx`）會讓文件採用套件主題。
  偏好設定可以是 `light`、`dark` 或 `system`（`src/shared/constants/appConfig.ts` 中的 `THEME_CONFIG.defaultTheme = "system"`）；`system` 會遵循 `prefers-color-scheme`）。`src/store/themeStore.ts` 中的 `applyTheme()`（由內嵌於 `src/app/layout.tsx` 的 `THEME_BOOT_SCRIPT` 同步處理，並在 hydration 前執行）會同時設定 `data-theme="dark"|"light"` 並切換 `<html>` 上的 `.dark` 類別。套件的深色 token 集合以 `data-theme="dark"` 為鍵（`packages/ui-kit/src/ci-tokens.css`）；OmniRoute 自身的深色覆寫（`globals.css` 中的 `.dark` 區塊）以及舊版 Tailwind `dark:` utilities 則以 `.dark` 類別為鍵。沒有強調色預設集：強調色始終來自套件，而較舊建置所持久化的預設集會在 store 載入時捨棄。
- **調色盤。** 有兩種，皆來自套件（`src/shared/constants/appearancePalette.ts`）：預設的 `editions` 和 `classic`。Editions 是 `<html>` 上套件的 `data-ci-appearance="editions"` 屬性，`ci-editions.css`（由 `ci-ui.css` 匯入）會將其與 `data-theme` 結合；Classic 則是不具備該屬性。根 layout 會在伺服器端渲染該屬性，因此沒有任何儲存資料的訪客（或沒有 JS 的訪客）在每個介面上都會取得 Editions — dashboard、登入頁面、`/status`、錯誤頁面、`/docs` 和 PWA。選擇會與主題一起持久化在相同的 `theme` store 中（`palette`、`setPalette()`、`applyPalette()` 位於 `src/store/themeStore.ts`），並由 `THEME_BOOT_SCRIPT` 在繪製前套用（`src/shared/utils/themeBootScript.ts`，內嵌於 layout 的 `<head>`），僅在儲存的 palette 為 `"classic"` 時移除該屬性；位於根 layout 外部的 `src/app/global-error.tsx` 會從相同 store 套用它。不要將 `data-ci-appearance` 放在任何其他元素上：套件會以 `html:root:has([data-ci-appearance="editions"])` 比對它，因此一個後代元素就會切換整份文件。Editions 的 `data-ci-editions-variant="landing"` 變體供行銷頁面使用，不適用於 dashboard。瀏覽器外觀：伺服器會在 `viewport.themeColor`（每個 `prefers-color-scheme` 各一個標籤）和 web manifest 中渲染預設值 Editions — `src/shared/constants/pwaThemeColors.ts` 中的 `PWA_THEME_COLORS`，也是 Editions `--ci-color-background`（`#f3f1e9` / `#11120f`）的唯一鏡像，並由 `tests/unit/pwa-theme-colors.test.ts` 固定對應至 `ci-editions.css`。之後即時的 `<meta name="theme-color">` 會遵循儲存的 palette 和模式：`THEME_BOOT_SCRIPT` 會在繪製前重寫標籤，而 theme store 的 actions 會在每次變更時執行此操作（`src/shared/utils/themeColorMeta.ts` 中的 `resolveThemeColor()` / `applyThemeColor()`，其中 `CLASSIC_PAGE_BACKGROUND` 取自套件的 `ciTokens`）。明確指定的 light/dark 主題會將每個標籤設為該模式；`system` 則會為每個 scheme 保留一個顏色。manifest 維持 Editions：每次安裝只擷取一次，不隨偏好設定變更。Monaco 會從 probe（`monacoKitTheme.ts`）讀取其顏色；在 Editions 下，probe 讀取會讓根部的 `data-theme` 翻轉一次同步執行，因為套件會從根部解析 Editions 的淺色/深色。
- **元件（介面卡）。** `src/shared/components/index.tsx` 保留 OmniRoute 元件 API（相同名稱、預設匯出和 props），其背後的 primitives 是套件的介面卡：表單（`Button`、`Input`、`Textarea`、`Checkbox`、`Select`、`Toggle`、`Badge`、`Card`）、覆蓋層與回饋（`Modal`/`ConfirmModal`、`Tooltip`/`InfoTooltip`、`NotificationToast`、`EmptyState`、`Loading`）、結構（`Collapsible`、`CollapsibleSection`、`SegmentedControl`、`Breadcrumbs`、`Avatar`）以及表格（`DataTable`、`FilterBar`、`ColumnToggle`、`FilterPills`、`PresetSlider`）。介面卡會依子路徑匯入套件元件，並將舊版 props 對應至其上 — 例如 `Button variant="primary"` 是套件的
  `default` button（`--ci-button-primary-*`：淺色模式中的反轉表面，深色模式中帶有
  `--ci-color-accent-foreground` 文字的強調色），`danger` 對應 `destructive`，而 `warning` 對應 `outline` 加上
  `.ci-button--warning` 擴充。`globals.css` 結尾（`@layer components`）的 `.ci-button--warning` 和 `.ci-badge[data-tone]` 規則，是建立在套件類別之上的 OmniRoute 擴充。
  `tests/unit/ui/adapters/*.test.tsx` 會固定每個介面卡的行為。
- **Shell。** `src/app/(dashboard)/layout.tsx` 會呈現 `DashboardLayout`，而 `DashboardLayout` 會呈現
  `src/shared/components/layouts/DashboardShell.tsx`：套件的 `SidebarProvider` / `Sidebar` /
  `SidebarInset`（`packages/ui-kit/src/sidebar.tsx`），以及 OmniRoute 位於
  `src/shared/components/Sidebar.tsx` 的導覽邏輯。「跳至內容」連結指向 `#main-content`，是第一個可取得焦點的
  元素。`src/shared/components/Header.tsx` 包含套件的 `SidebarTrigger`（Shell 唯一的側邊欄切換控制項）、Keak 的
  `ProductSwitcher` 和命令面板開啟按鈕；只有在 `#main-content` 內未掛載套件的 `PageHeader`（`.ci-page-header`）時，
  才會顯示路由標題，因此包含自身 `PageHeader` 的頁面只會有一個 `h1`。`src/shared/components/CommandPalette.tsx`
  是套件的 `Dialog`。
- **圖示。** `<Icon name="material_name">`（`src/shared/components/Icon.tsx`）會透過
  `ICON_MAP`（`src/shared/constants/iconMap.ts`），將名稱（畫面使用的 Material Symbols 詞彙）解析為 Lucide
  圖示。Material Symbols 字型和套件已移除：對應表中缺少的名稱會呈現中性的預留圖示
  （`data-icon-missing="true"`），並在非 production 環境記錄主控台警告。
  `npm run gen:icon-map` 會列印目前使用但對應表中缺少的名稱
  （`tests/unit/icon-map-coverage.test.ts` 會對任何沒有 Lucide 圖示的名稱測試失敗；
  `tests/unit/icon-map-object-values.test.ts` 涵蓋儲存在查詢物件中的名稱）；
  `scripts/dev/codemod-material-icons.mjs <dir|file>... [--write]` 會將字面值
  `<span className="material-symbols-outlined">` 元素重寫為 `<Icon>`。
- **品牌。** `src/shared/components/OmniRouteLogo.tsx` 包裝套件元件：預設匯出 `OmniRouteLogo`
  會呈現 `ProductIcon product="omniroute" variant="glyph"`（內嵌 SVG，安全支援 `basePath`），而
  `OmniRouteLockup` 會呈現 `ProductLockup product="omniroute"`（可存取名稱為「Keak OmniRoute」），或對於白牌營運商，
  呈現其自有的 `name`/`logoSrc`。產品切換器的目的地位於
  `src/shared/constants/keakProducts.ts`（`KEAK_PRODUCT_LINKS`、`KEAK_ACTIVE_PRODUCT`）。獨立頁面
  — `src/app/login/page.tsx`、`src/app/status/page.tsx`、`src/app/maintenance/page.tsx`、
  `src/app/offline/page.tsx`、`src/app/not-found.tsx` 和 `src/shared/components/ErrorPageScaffold.tsx`
  — 會顯示品牌組合標誌；`tests/unit/brand-pages-static.test.ts` 會對此進行防護。

## 2. 規則

1. 使用 Token，絕不使用字面值。有意保留的例外：永遠深色的主控台終端機，以及
   `STATUS_HEX` (`src/shared/constants/statusColors.ts`)，這是套件狀態調色盤中解析後的十六進位鏡像，
   供需要字面十六進位值的呼叫端使用。分類調色盤不再是例外：
   它們透過 `src/shared/utils/categoricalPalette.ts`，以及針對路由策略的
   `src/app/(dashboard)/dashboard/combos/strategyPalette.ts`，
   依照套件序列順序使用套件的八個圖表 Token（`--color-chart-1..8`，加上 `-ink`/`-subtle`）。
   ReactFlow 邊線與編排畫布則讀取主題感知的 `--orch-status-*` 變數
   (`src/shared/components/flow/edgeStyles.ts`)。
2. 絕不要手動修改 `packages/ui-kit/src`：使用 `scripts/dev/sync-ui-kit.sh <commit>` 同步；
   預先提交閘門 `npm run check:ui-kit-snapshot` (`.husky/pre-commit`) 會在任何位元組與釘選的上游提交
   不同時失敗（當上游複本、`UI_KIT_CLONE` 或 `_references/cheaper-inference-ui-kit` 不存在時，
   會發出警告並略過）。當套件缺少某項功能時，請在介面卡或畫面中迂迴處理，並向上游提出需求。
3. 套件文字預設值為英文（`label = "Loading"`、`loadingLabel = "Loading table"`……）——每當套件元件呈現文字時，
   請傳入來自 `useTranslations(...)` 的翻譯字串。
4. Tailwind 工具類別優先於套件元件類別（套件宣告
   `@layer theme, base, components, utilities`，且其規則位於 `components`）——間距與版面配置請使用工具類別，
   不要用它們重新著色套件元件。
5. 標題：頁面與區段標題使用 `.ci-heading`；只有錯誤頁面的狀態碼等大型、稀疏的展示文字才使用
   `.ci-dashboard-display`。兩者皆使用 Switzer。
6. `tests/unit/dashboard-kit-sweep.test.ts` 會守護套件的採用情況：`src/app` 或 `src/shared/components` 下不得有 Material ligature span；
   在儀表板樹狀結構中（`src/app/(dashboard)` 與 `src/shared/components`），不得有原生 `<select>`、`<textarea>` 或 `<table>`，
   也不得有列出的例外以外、手動建立的 `role="dialog"`（`Select` 介面的原生分支、
   `RequestLoggerDetail`）；其中每個原生 `<button>` 或 `<input>` 都需要有包含 `kit-exception:` 的註解（附上原因），
   且該註解結束位置距離它最多 3 行；調色盤色相與 `dark:` 變體只能出現在測試列出的檔案中。
7. 在 PR 前驗證兩種主題與 390 px 視窗大小（螢幕截圖）；`tests/e2e/a11y.spec.ts` 會執行
   axe。

## 3. 新增畫面

1. 頁面以 kit 的 `PageHeader`(`@omniroute/ui-kit/page-header`,在 dashboard 內使用
   `compact`)開頭——包含標題、描述與 `actions`。外層 shell 標頭隨後會捨棄自己的標題。
2. 使用 `@/shared/components`(即 adapter)建構控制項;在沒有 adapter 的地方,透過子路徑
   (subpath)使用 kit 元件(`Table`/`TableScrollArea`/`DataTableShell`、`Field`、`Alert`、
   `Tabs`、`RadioGroup`、`Slider`……)。
3. 圖示:`<Icon name="…" />`。新名稱需加入 `ICON_MAP`,並搭配語意相符的 Lucide 元件;
   `npm run gen:icon-map` 會列出仍缺少的名稱。
4. 顏色:語意化工具類別(`text-success`、`bg-warning-bg`、`border-border`……),圖表系列使用
   `var(--color-chart-N)`;不使用 hex 值,也不使用只是重複同一顏色的 `dark:` 變體。
5. 文字:每個字串,包括傳給 kit 元件的標籤,都必須來自 `useTranslations`。新的 key 加入
   `src/i18n/messages/en.json`、`pt-BR.json` 與 `vi.json`(越南語同位測試會釘住每個英文
   key);其他語系由 i18n 同步補齊。
6. 提交 PR 前執行各項把關:`tests/unit/dashboard-kit-sweep.test.ts`、
   `tests/unit/icon-map-coverage.test.ts`、`tests/unit/icon-map-object-values.test.ts`、
   `npm run check:dashboard-typecheck`(唯一能抓到 `iconMap.ts` 中重複 import 的檢查)、
   `npm run check:ui-icu`,以及該畫面本身的測試。

## 4. 新增或變更轉接器

1. 維持 `src/shared/components/index.tsx` 的公開 API：相同的匯出名稱、預設匯出以及接受的 props。在轉接器內部將舊有 props 對應到 kit（參考 `Button.tsx`：`VARIANT_TO_KIT`、`SIZE_TO_KIT`）。
2. 以子路徑匯入 kit（`@omniroute/ui-kit/<component>`）。
3. 針對 kit 缺口的變通做法應放在轉接器中（若修正屬於樣式，則放在 `globals.css` 的 `@layer components`），絕不放在 `packages/ui-kit/src`。
4. 新增或更新 `tests/unit/ui/adapters/<name>.test.tsx`。對於有許多呼叫方的轉接器，請比較變更前後渲染出的標記——內距或包裝層的變動會擴散到每個畫面。

## 5. 更新套件

`npm run check:ui-kit-upstream`將`packages/ui-kit/UPSTREAM.md`中固定的版本與上游儲存庫的最新`v*`標籤進行比較，並在發佈時列印同步命令。

每日`UI Kit upstream watch`工作流程 (`.github/workflows/ui-kit-upstream-watch.yml`) 執行相同的檢查。當 pin 位於後面時， `scripts/ci/ui-kit-sync-pr.sh`會在滾動分支`chore/ui-kit-sync-latest`上針對最高`release/vX.Y.Z`分支保持一個同步PR開啟。它永遠不會合併：每個套件版本仍然需要對本地VPS進行目視檢查。當新版本發佈時，分支會被重建，否則就不會發生。手動提交的開放PR不會被覆蓋，並且維護者關閉未合併的版本的PR將保持關閉狀態，直到新版本發布。

當無法開啟PR時（目標版本被凍結、 PR已手動提交、 PR已關閉或未設定PR令牌），工作流程會保持一個追蹤問題處於開啟狀態，並說明原因。

這個工作流程使用兩個秘密：

- `secrets.UI_KIT_READ_TOKEN`：私有上游儲存庫的唯讀令牌。當工作流程無法讀取上游（沒有令牌、令牌停止工作或GitHub無法存取）時，運行將保持綠色，但會寫入一條警告並保持一個單獨的問題處於開啟狀態，一旦稍後的運行可以再次讀取上游，該問題就會自行關閉。
- `secrets.UI_KIT_SYNC_PR_TOKEN`：此儲存庫上的細粒度令牌，具有內容和拉取請求寫入權限。預設的`GITHUB_TOKEN`不能在這裡建立PRs ，而且它開啟的PR不會觸發CI。如果沒有此令牌，工作流程只會推送分支。

`scripts/dev/sync-ui-kit.sh <commit|latest> [clone]`將該提交處的上游`src/` （`latest` =最新的`v*`標記）複製到`packages/ui-kit/src`中，應用單一允許的轉換（它從相對導入中刪除`.js`後綴），並將`packages/ui-kit/package.json`和`package-lock.json`中的工作區版本設定為上游版本。然後：檢視`git diff packages/ui-kit`，對兩個主題中的提供者、設定、組合、用法和端點進行視覺化傳遞，運行`npm run check:ui-kit-snapshot`和`npm run test:vitest:ui`，並使用上游變更日誌開啟PR 。

## 6. README 圖表

根目錄 `README.md` 嵌入的十二張圖表（`docs/diagrams/*.svg`）是將套件套用至靜態影像的結果，而且它們是產生的，並非手工繪製：共有 13 個位於 `scripts/docs/gen-readme-*.mjs` 的產生器檔案（十二張圖表加上 `gen-readme-diagrams.mjs` 驅動程式），以及 12 個位於 `tests/unit/docs/readme-*-svg.test.ts` 的過時狀態測試，每張圖表各一個；每個測試都會逐位元組比較已提交的檔案與其產生器的輸出（工作 `test-unit`）。

- **權杖。** `scripts/docs/readme-diagram-theme.mjs` 會從 `packages/ui-kit/src/ci-editions.css` 複製 Editions 調色盤（預設外觀）（由 `tests/unit/docs/readme-diagram-theme.test.ts` 鎖定至該檔案；此測試也會檢查兩種配置中，每個表面上的每種文字色彩是否符合 WCAG AA；唯一的例外是淺色 `warn`，它是將套件的警告色加深 10 %，因為套件值在畫布上的對比度為 4.46:1），並依照套件的字級比例（`ci-tokens.css`）定義文字角色：所有內容皆使用 Switzer，以及套件所定義的字重（400/500/600，展示文字為 500）和字距，但程式碼角色（`.cmd`、`.term`、`.term-lg`、`.mono`、`.mono-sm`、`.mono-xs`）除外；這些角色使用 IBM Plex Mono，且僅用於命令、URL、識別碼與終端機畫面。
  淺色值位於 `:root`，深色值則在檔案內的 `prefers-color-scheme: dark` 後方，因此每張影像都會在 GitHub 上跟隨檢視者的配置。
- **字型。** GitHub Markdown 不包含 CSS，而 camo Proxy 會封鎖所有外部擷取，因此套件字型必須包含在檔案內。`scripts/docs/readme-outline.mjs` 是每個產生器的最後一個步驟，會使用 HarfBuzz 塑造 Switzer 角色，並將它們繪製為向量輪廓（`<defs>` 路徑和 `<use>`）；Switzer 缺少的箭頭與幾何符號則會依其自身的度量繪製。請使用輪廓，絕不可嵌入字型：Switzer 的授權條款（`packages/ui-kit/src/fonts/FFL.txt`）禁止在未取得書面同意的情況下進行子集化與格式轉換，但允許向量繪圖，因此請勿重新引入 Switzer `@font-face` 或 `data:` URI。檔案中唯一保留的字型，是用於仍維持為實際程式碼文字之內容的 OFL IBM Plex Mono 子集（`scripts/docs/readme-fonts.mjs`），並由這些字元建置；任何無法嵌入的字符都會擲回錯誤。
- **重新產生。** `npm run docs:readme-diagrams` 會依照 README 中的順序重寫全部十二個檔案，並為每個檔案輸出一行及其大小。單一產生器也可獨立執行（`node scripts/docs/gen-readme-<name>.mjs`；`free-tier-budget` 需要使用 `node --import tsx/esm`，因為其數值來自 `open-sse/config/freeModelCatalog.ts` 中的即時目錄載入器；目錄變更所造成的 CI 影響記載於 `docs/architecture/QUALITY_GATES.md` → `docs-sync-strict`）。請一併提交產生器與 SVG。
- **驗證。** `scripts/docs/readme-svg-shots.mjs <file.svg> <outdir>` 會按照 GitHub 提供檔案的方式呈現檔案（`<img>` 標籤、camo 的 `Content-Security-Policy`、`image/svg+xml`），擷取淺色與深色畫面，並回報頁面發出的外部字型請求數量（必須為 0）。
- **大小限制。** 每個檔案須低於 200 KB（每個過時狀態測試都會判定）；500 KB 是任何 README 影像的硬性上限（SVG Studio 驗證器的規則）。
- **文案維持不變，數值取自閘門。** 品牌重塑僅變更字型與調色盤，而不變更文字：每個產生器都會將其圖表的文案保存在 `*_COPY` 常數中（或從即時目錄建置），該常數既是繪製的文字，也是輪廓化步驟的輸入。標準數值會保留在 `<text>` 節點中（輪廓化後不可見，`fill-opacity:0`），由 `check:docs-counts`（`scripts/check/check-docs-counts-sync.mjs`）讀取；閘門所讀取圖表的過時狀態測試，也會在產生的檔案上執行其驗證器，因此若數值與程式碼不一致，測試便會失敗——請修正閘門所讀取的來源，絕不要修改產生器中的數字。
